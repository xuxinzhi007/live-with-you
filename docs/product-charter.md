# 《雯宝》产品宪章 · V2

> 状态：2026-10-29 起生效。方向由“观察雯宝生活”调整为“玩家扮演雯宝、亲自玩”。
> 旧版“观察向”文档（`mobile-portrait-layout-research.md`、`mobile-scene-scale-research.md`、
> `multiplayer-portrait-scene-design.md`）仅作历史参考，与本文件冲突时以本文件为准。

## 一句话定义

《雯宝》是竖屏、单手、低压力的小世界生活游戏：**玩家就是雯宝**，在可走动的房间里照料植物、
使用家具、和世界产生小互动，把每天几分钟的游玩变成看得见的房间与收藏变化。

本文件约束产品、交互、内容与技术。新增功能必须通过文末偏离检查。

## 北极星体验

打开 5 秒内，玩家应知道“我现在能做什么”；30 秒内完成一次有即时反馈的互动；
几天后，房间、花圃、收藏和小记能看出自己做过什么。

界面不是任务清单，也不是后台面板。它首先是一个能走进去、能碰到东西的房间。

| 体验支柱 | 玩家感受 | 系统表达 |
| --- | --- | --- |
| 我在场 | 我控制的就是她，不是看别人 | 点地走动、走路帧、朝向、镜头跟随、碰撞 |
| 世界内操作 | 想做什么就走过去做 | 点物件 → 走近 → 情境按钮；门是唯一跨房间入口 |
| 即时反馈 | 每次操作都有回应 | 动作、姿态、气泡、物件状态、轻音效/震动（可选） |
| 长期留痕 | 做过的事留在房间里 | 花圃、花束、收藏、纪念、生活小记、房间朝向 |
| 低压力 | 关掉也没关系 | 无失败、无体力墙、无签到、无红点、短冷却不阻断其他内容 |

## 参考作品的取舍

- 空间与手感参考《月兔奥德赛》：世界本身是界面，互动要有可读的动作反馈。
- 竖屏与底栏参考《动物森友会：口袋营地》：底栏少而稳，互动时 HUD 让路。
- 节奏参考《旅行青蛙》《猫咪后院》：低压力、等待是期待，不是付费墙。
- 不借鉴：红点驱动、任务清单、体力、抽卡、排行榜、陌生人房间大厅。

## 绝不做什么

1. 每日任务清单、签到、红点、倒计时催促。
2. 用体力、失败或数值门槛阻止核心游玩；同一物件的短冷却必须有可见倒计时，且不能阻止玩家去别处玩。
3. 以菜单按钮领奖为主的玩法；奖励必须来自世界内行为。
4. 首页常驻大数值面板、满屏 HUD 或后台仪表盘式布局。
5. 只有物品数量、没有独特行为与长期变化的扩展。
6. 与角色、空间、记忆无关的泛化小游戏、抽卡或付费随机。
7. 把“玩”做成必须每日上线才能维持的进度系统。

一票否决：移除雯宝和她的小屋后，这项功能仍可换皮成任意农场或放置手游，则不属于核心方向。

## 核心循环

进入房间 → 看到当前可做的事（情境按钮 + 地面/物件轻提示） → 走过去并交互 →
获得动作、文案、物件状态等即时反馈 → 留下零钱/花种/花束/纪念/小记 →
下次打开看到房间与收藏的变化。

| 会话时长 | 玩家行为 | 合格反馈 |
| --- | --- | --- |
| 5–15 秒 | 走两步、点一个物件 | 走路动作、朝向、交互姿态、一句文案 |
| 30–90 秒 | 休息、种花、浇水、踢球 | 数值与环境变化、物件状态、短动作 |
| 2–3 分钟 | 跑一趟庭院/街区、买种、收花 | 资源闭环、收藏与小记、房间可见变化 |
| 数天 | 回来看花、看收藏与小记 | 新状态，不是错过惩罚 |

精力、心情只用于表达与建议，绝不能成为游玩门槛。

## 交互规范

| 玩家意图 | 正确入口 | 禁止替代 |
| --- | --- | --- |
| 移动 | 点地面（自动寻路到可行走带） | 虚拟摇杆、方向键常驻 |
| 使用物件 | 点物件 → 角色走近 → 底部单一情境按钮 | 远处直接弹效果、菜单瞬移 |
| 出门 | 点门 → 抵达后切房间 | 顶栏地点 Tab 瞬移 |
| 收获 | 点花圃，按生长阶段给“种/浇/收” | 纯背包列表领取 |
| 查看收藏/小记 | 底栏抽屉 | 常驻信息面板 |
| 轻动作 | 庭院踢球 → 球飞出后点球接住 | 自动结算、看广告复活 |

- 装饰物（地毯、绿植等）不是点击目标，不能吞掉地面点击。
- 一次点击只做一件事：物件 > 角色 > 地面。
- 手持/飞行中的球可以被点按接住；接不到不惩罚，只重置连击。
- 镜头默认跟随；手动拖镜头后暂停跟随，再次移动或交互时温和恢复。
- 反馈顺序：动作/位移 → 文案/气泡 → 物件状态 → 少量特效 → 数值。前四项缺失时不能只弹数字。
- 尊重 `prefers-reduced-motion`：关闭走路帧切换、镜头缓动与循环动画，保留状态变化。

## 移动端 HUD 预算（390 × 844）

- 顶部：身份胶囊（头像 + 名字 + 当前房间/时段）+ 两枚资源胶囊。
- 底部：至多 3 项（背包 / 手账 / 更多）。
- 场景内：至多一个情境按钮 + 一条短提示；不设常驻地点条。
- 常驻内容 HUD（顶部身份 + 底栏）不超过屏高 15%，不含系统安全区；抽屉不得超过 40dvh。
- 所有触控目标 ≥ 44px；场景中心与角色脸不被遮挡。

## 内容合同

### 新房间

至少包含：独有背景与光照、2 个可交互物件、1 个长期资源或故事线、1 个清晰的门/出口、
1 条可行走带且不被装饰物截断。

### 新物件

至少包含：清楚的视觉身份、与角色同尺度的尺寸、可站立的前方区域、抵达后才结算的动作、
可见反馈、以及收藏/资源/小记中的一种长期意义。

### 新动作

必须是世界内发生的动作，有动作或物件状态反馈；不引入失败惩罚；不新增每日次数限制。

## 技术边界

- React + TypeScript 负责 DOM HUD、抽屉、文案与路由；PixiJS 负责世界渲染、输入、相机与角色动画。
- 世界使用固定逻辑坐标（世界高 1000，横向按房间加宽），渲染按屏幕高度等比缩放；不再用百分比把家具压成图标。
- 存档只保存序列化数据；新增字段必须兼容旧档，并在 `normalizeGameState` / `normalizeWorldState` 中给默认值。
- 资源、房间、物件、动作以数据声明进入（`src/mobile/world/rooms.ts` 等），避免堆单个条件分支。
- 多人、云存档、好友拜访是后端阶段；线上没有实时中继时不得用本地通道假装完成。

## 版本路线

### V0.3：可走动的单主角小世界（当前）

- 玩家操控雯宝，在三个房间间走动、互动。
- 种植 / 浇水 / 收花的闭环，街区买种。
- 接球轻动作与连击纪念。
- 3 项底栏、单情境按钮、抽屉式背包/手账/更多。
- 旧移动端保留在 `?legacy`，桌面保留在 `?desktop`。

### V0.4：内容与手感

- 每个房间补足 2 个以上有独特反馈的物件。
- 家具朝向、坐下/躺下等更多姿态；音效与轻震动。
- 真机 360–430px 回归、低端机性能、无障碍。

### V0.5：关系与上线

- 生活小记与收藏形成可回看的故事线。
- PWA 更新策略、云存档评估。
- 实时共处需要真实后端后再评估，不作为前置条件。

## 每次开发前的偏离检查

1. 玩家能在场景里发现并操作它吗？
2. 操作后是否有明确、可见的反馈（动作/物件/文案）？
3. 是否留下房间、收藏、资源或小记中的长期痕迹？
4. 它是低压力选择，还是伪装成奖励的每日任务？
5. 390px 宽手机上是否不遮挡角色与主要场景，且单手可完成？
6. 去掉资源数字后，它是否仍然只属于雯宝和这个房间？
7. 旧存档、离线和性能较差设备会怎样？

第 1、2、3 项中有两项为否，或第 4 项属于任务/催促，则必须重设计或拒绝。

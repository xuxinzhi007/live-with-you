# 《雯宝》产品宪章

## 一句话定义

《雯宝》是以《月兔奥德赛》为核心体验的移动端陪伴生活游戏：玩家观察雯宝在可布置的小世界中生活，通过探索、轻互动与长期收集，让场景和关系慢慢长出故事。

本文件是产品、交互、内容和技术开发的共同约束。新增功能必须通过文末偏离检查，否则不进入开发。

## 北极星体验

打开游戏后，玩家应在五秒内感到：“雯宝今天正在过自己的生活，我想看看发生了什么。”

不是任务清单、数值面板或不知道该点什么的网页工具。三十秒内应完成一次有角色反馈的互动；数天后应能从房间、收藏和小记看出共同经历留下了痕迹。

| 体验支柱 | 玩家感受 | 系统表达 |
| --- | --- | --- |
| 可观察的生活 | 她不是等待点击的玩偶 | 自主散步、看窗、坐下、抱球、天气和时段行为 |
| 空间叙事 | 场景会讲故事 | 家具、花园、照片、纪念架、地点氛围 |
| 轻主动性 | 我能介入，但不被逼迫 | 点角色、点物件、拖球、出行、布置 |
| 长期留痕 | 今天的事会留在以后 | 花束、收藏、生活小记、角色习惯、地点扩展 |
| 低压力 | 关掉也没关系 | 无失败、无体力墙、无连续登录惩罚 |

## 参考作品的取舍

- 主参考《月兔奥德赛》：空间本身叙事、角色自主生活、物件和关系留下可见痕迹。
- 节奏参考《旅行青蛙》《猫咪后院》：低压力、打开有新发现、等待是期待而不是付费墙。
- 内容结构参考《动物森友会：口袋营地》：地点、收集、布置与关系构成长线；不借鉴任务压力、货币膨胀或红点驱动。

## 绝不做什么

1. 每日任务清单、签到、红点、倒计时催促。
2. 用体力、失败或数值门槛阻止与雯宝互动。
3. 以菜单按钮领奖为主的玩法；奖励必须来自世界内行为。
4. 首页常驻大数值面板、满屏 HUD 或后台仪表盘式布局。
5. 只有物品数量，没有独特行为、故事入口和长期变化的扩展。
6. 与角色、空间、记忆无关的泛化小游戏。

一票否决：移除雯宝后，这项功能仍可换皮成为任意农场或放置手游，则不属于核心方向。

## 核心循环

观察今天正在发生的片段 → 在空间中发现角色、物件和出口 → 轻介入（互动、拖球、出行、布置） → 获得角色动作、台词、环境变化等即时反馈 → 留下花园、收藏、照片、小记等长期痕迹 → 下次打开发现新状态。

| 会话时长 | 玩家行为 | 合格反馈 |
| --- | --- | --- |
| 5–15 秒 | 看今天的片段、点角色 | 角色动作、台词或镜头反应 |
| 30–90 秒 | 点家具、陪玩、街区偶遇 | 角色先走到目标，世界或收获变化 |
| 2–3 分钟 | 出门、带回物品、种花、布置 | 产生可见长期变化 |
| 数天 | 看花开、看小记、看收藏和习惯 | 新片段，不是错过惩罚 |

心情、饱腹、精力和亲密只能提供角色表达与建议，绝不能成为游玩门槛。

## 交互规范

| 玩家意图 | 正确入口 | 禁止替代 |
| --- | --- | --- |
| 陪伴 | 点角色、轻拖、抛球 | 固定“摸头/玩耍”菜单按钮 |
| 使用家具 | 点家具，角色走到后互动 | 菜单直接播放动画 |
| 出门 | 点门、楼梯、路口，角色先抵达 | 顶部 Tab 瞬移 |
| 收获 | 点花圃、纪念架、可见物件 | 纯背包列表领取 |
| 布置 | 进入布置后直接拖家具 | 格子强制或影响角色 |
| 回忆 | 点相框或纪念架 | 常驻任务历史面板 |

- 手动拖动场景后，镜头不强制拉回；角色互动真正开始后，镜头温和恢复跟随。
- 自主行为不得走向门、楼梯、花圃、物理道具等系统入口。
- 反馈顺序：角色移动/动作 → 台词/声音 → 物件状态变化 → 少量特效 → 背包数字。前四项缺失时，不能只弹数字奖励。

## 移动端 HUD 预算

- 顶部中间：一条可忽略的生活线索，不超过一行。
- 右上角：可展开背包，显示资源、天气和线索。
- 左上 PC / 底部手机：雯宝、布置、更多；数值与设置只在更多中展开。
- 场景中间和下方中间保持可看、可点；物件提示和角色气泡只在情境中短暂出现。
- 手机触控目标不小于 44px；低性能设备禁用高频全屏特效；尊重减少动态效果。

## 内容合同

### 新地点

每个地点至少有：独有环境氛围、两个可发现的世界内互动、一个角色自主行为、一个和其他地点往返的资源或故事线、一个清晰的世界内出口。

### 新物件

每个可交互物件至少有：清楚的视觉身份和触区、角色抵达后才结算、角色或物件可见反馈、需求/收藏/布置/故事/地点关系中的一种长期意义。

### 新事件

事件必须是在世界里遇见的事，不是任务列表；提供无对错的两种倾向选择；每日结算有限，重复造访成为陪伴而非刷资源；关键选择写入生活小记或改变可见物件。

## 技术边界

- React + TypeScript 负责 DOM UI、场景声明、布局、回忆录和弹窗；游戏运行时负责输入、摄像机、角色、物理和事件。
- 存档只保存序列化数据，不能保存 DOM、相机或渲染对象；新增字段必须兼容旧存档。
- 资源、地点、事件应以数据声明进入，避免继续堆积单个条件分支。
- 多人、云存档、好友拜访是后端阶段，不能用 localStorage 假装完成。

## 版本路线

### V0.2：可玩的生活原型

- 小屋首页成为“雯宝今天正在做什么”。
- 核心家具都有生活行为与可见反馈。
- 出行、街区、阳台、咖啡店完整走通。
- HUD 降噪，移动端单手完成核心互动。
- 真机手势、性能、存档回归。

### V0.3：关系与空间成长

- 角色习惯和亲密关系台词。
- 花种/花束的多样用途。
- 家具和收藏的可见解锁。
- 更丰富的天气、时段与地点故事变体。

### V0.4：上线准备

- PWA 更新策略、云存档/账户方案、内容配置化与调试工具。
- 无障碍、性能、异常恢复、真机和桌面端完整验收。
- 可选异步分享/好友拜访；实时多人不是前置条件。

## 每次开发前的偏离检查

1. 玩家能在场景中发现并操作它吗？
2. 雯宝是否会有明确、可见的反应？
3. 是否留下空间、记忆、关系或世界状态的长期痕迹？
4. 它是低压力选择，还是伪装成奖励的每日任务？
5. 在 390px 宽手机上，是否不遮挡角色和主要场景？
6. 去掉资源数字后，它是否仍然只属于雯宝和这个地点？
7. 旧存档、离线和性能较差设备会怎样？

第 1、2、3 项中有两项为否，或第 4 项属于任务/催促，则必须重设计或拒绝。

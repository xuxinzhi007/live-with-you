# 雯宝 · 服务端接线（陪伴 / 出图 / 资源库）

> 客户端只调同源路径，实际转发在 Vite 中间件（开发）或 Netlify Function（生产）。
> 环境变量见 `.env.example`；**不要**给服务端变量加 `VITE_` 前缀，否则会被打进前端包。

## 1. 三个外部件

| 部件 | 地址 | 谁用 |
| --- | --- | --- |
| 局域网 Ollama | `http://192.168.124.77:11434`（`qwen2.5:3b-instruct`） | 密语陪伴 |
| 本机 ComfyUI | `http://127.0.0.1:8188` | 幻阁裁缝铺出图 |
| 资源库（暂停） | `http://192.168.124.77:8788` | 图片资源；默认关闭，见 [现行状态 §4](./现行状态.md) |

## 2. 陪伴：`/.netlify/functions/companion-scene`

- 实现只有一份：`netlify/functions/companion-scene.mjs` 导出 `handleCompanion`。
- **开发**：`vite.config.ts:183` 的中间件把同源请求交给同一个 `handleCompanion`，所以本地和线上行为一致。
- **生产**：Netlify 直接按 `netlify.toml` 的 `functions = "netlify/functions"` 部署，超时 26s。
- 客户端：`src/mobile/world/companion-bridge.ts`，`GET` 探活（3.5s 超时）、`POST` 对话；失败回退本地台词，不报错、不阻塞 UI。
- 变量：`OLLAMA_BASE_URL`、`OLLAMA_MODEL`、`OLLAMA_API_TOKEN`（云主机网关才需要）。

## 3. 出图：`/api/comfy/draw` —— **仅开发环境**

- 只在 `vite.config.ts:93` 的 dev 中间件里存在：拼官方 Qwen 图 → `POST /prompt` → 轮询 `/history/{id}` → `/view` → base64 dataURL 返回。
- 生产 `netlify/functions/` 里**没有**对应函数，也没有重写到`/api/comfy/draw` 的规则 → 线上点「绘制」必定 404。
- 客户端调用点：`WorldApp.tsx` 的 `handleLiveComfyGenerate`，**没有 `import.meta.env.DEV` 保护**。
- 参数：`COMFY_BASE_URL`（默认 `http://127.0.0.1:8188`），超时约 240s。
- 返回图直接写进 `nikki.customImages`（`localStorage`，dataURL）。单张 3–4MB，5MB 配额下写 1–2 张就溢出 —— 这是已知风险，属客户端待修项。

## 4. 资源库探活

- `probeRemoteAssets()` 打 `/files/base/original-idle.webp`，2s 超时；`VITE_ASSET_BASE_URL` 为空直接判 `down`，走本地。
- 单张图失败的回退 helper `applyLocalAssetFallback` 已写好但**没人调用**（见 [现行状态 §3](./现行状态.md) 断点 5）。

## 5. 开发与生产的差异清单

| 能力 | 开发 `npm run dev` | 生产 `npm run build` + Netlify |
| --- | --- | --- |
| 密语 | ✅ 同源中间件 → Ollama | ✅ Function（需在后台配 `OLLAMA_*`） |
| 裁缝铺出图 | ✅ 127.0.0.1:8188 | ❌ 无函数，404 |
| 资源库 8788 | 需显式配 `VITE_ASSET_BASE_URL` | 同左（构建期注入） |
| 存档 | 浏览器 localStorage | 同左；`VITE_WENBEBI_SAVE_URL` 未接入 |

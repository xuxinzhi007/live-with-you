# 《雯宝》当前实现总结与下一步方向

> 依据：[产品宪章](./product-charter.md)  
> 状态：V0.2 可玩的生活原型，**骨架已形成，首屏体验与移动端手感尚未达标**。

## 1. 当前项目是什么

当前项目是一个部署在 Netlify 的 React + TypeScript + Vite 浏览器游戏原型。它已经从单页桌面宠物扩展成多地点生活空间，主玩法不是传统任务列表，而是让雯宝在场景中移动、互动、收集和留下回忆。

当前技术分工：

| 模块 | 位置 | 当前职责 |
| --- | --- | --- |
| React UI | `src/App.tsx` | 场景 DOM、布置、回忆录、HUD、引导、弹窗 |
| 游戏运行时 | `src/game/runtime.js` | 输入、摄像机、道具物理、事件、资源、天气、进度 |
| 角色行为 | `src/game/pet.js` | 状态、行走、互动动作、自主生活 |
| 场景数据 | `src/game/data/room.js` | 地点物件、互动类型、可移动家具 |
| 样式 | `styles.css` | 场景、角色、HUD、移动端适配和特效 |

## 2. 已实现能力

### 场景与出行

- 小屋、阳台、街区、街角咖啡店四个地点。
- 不再通过顶部 Tab 直接切换；玩家点击门、楼梯或路口后，雯宝会先走到出口，再选择目的地。
- 街区成为连接节点，可回家、上阳台、去咖啡店。
- 手动浏览场景会停留在玩家视角；角色相关互动启动后，镜头恢复温和跟随。

### 角色与世界内互动

- 点角色：摸头、不同部位反应、双击踢飞、拖拽与落地恢复。
- 点家具：雯宝先走到床、点心、唱片机、藤椅、吧台、窗边桌等物件再互动。
- 玩具球：可拖起、抛出、重力落地、反弹、角色实时追球、持有、放回玩具筐。
- 接球默契：真实抛球并成功追到三次，获得纪念并写入生活小记。
- 自主生活：雯宝会在可互动家具之间走动、休息和观察；出口、花圃、物理道具已排除在随机行为外。

### 探索、成长与长期留痕

- 街区的喷泉、花摊、长椅提供有选择的偶遇。
- 每个街区点每日只结算一次资源；完成后转为可陪伴但不刷资源的安静状态。
- 天气与时段提供事件变体；晴天、有风、小雨每天稳定生成，小雨可自动浇一次已种花圃。
- 零钱 → 花种 → 阳台种植/浇水 → 开花 → 花束的可重复成长链路。
- 小纪念会逐步填充小屋旅行纪念架；花束与纪念在场景中可见。
- 回忆录支持照片上传压缩、本地保存，以及自动生成的生活小记。

### 布置、存档和部署

- 可移动家具支持自由拖动、允许重叠、限制在房间内；角色和玩具不受布置影响。
- 状态、布局、玩具位置、花园、资源、天气、每日事件、照片和小记均使用 localStorage 保存，并尽量兼容旧存档。
- PWA Manifest 和 Netlify 静态部署基础已具备。
- `npm run build` 当前通过。

## 3. 与产品宪章的差距

这是下一阶段的判断依据，不能用“已经有很多系统”掩盖体验差距。

| 宪章要求 | 当前状态 | 判断 |
| --- | --- | --- |
| 5 秒内看见“雯宝今天在做什么” | 有自主行为和顶部生活线索，但打开时没有稳定、可读、具叙事感的今日片段 | **最高优先级缺口** |
| 世界本身讲故事 | 有地点、家具、花园、纪念架，但场景变化仍偏符号化，物件和当天故事关联不足 | 需要重做小屋首页叙事层 |
| 世界内操作优先 | 已基本达成：角色、家具、出口、玩具都在世界内操作 | 保持，不要回退为菜单按钮 |
| 长期可见成长 | 花园、花束、纪念架、小记已经成立 | 需让它们更具体地影响场景和角色习惯 |
| 低压力节奏 | 无体力墙、无任务清单、每日资源有限但可陪伴 | 基本达成，注意不要演变成每日打卡 |
| 低遮挡移动端 HUD | 已开始收束为顶部线索、背包、底栏 | 真实手机的视觉和手势仍未完成验收 |
| 新内容数据化 | `roomSpots` 已数据化，但事件、资源、旅行规则集中在 `runtime.js` | V0.3 前需要拆分内容数据与模拟规则 |
| 上线可维护性 | 基础构建和本地保存可用 | 缺少真机 QA、自动测试、云存档、错误监控和内容调试工具 |

## 4. 下一步唯一主目标：重做“小屋首页的今日片段”

### 为什么先做它

《月兔奥德赛》式体验的关键不是地点数量，而是玩家打开后看到一个正在发生的小故事。当前项目的四个地点、天气、资源链已经够支撑这一层；继续加新地点只会让体验更分散。

### 要实现的体验

进入小屋后，雯宝已经处于一个有原因的生活状态，而不是站在空房间等待点击：

- 下雨天：靠窗看雨、台灯暖光或准备休息。
- 精力低：靠近床/藤椅，表达想休息。
- 饱腹低：朝点心或咖啡店产生倾向。
- 有花束/纪念：可能在纪念架或相框前停留。
- 玩具刚被拿出：可能抱球或看向玩具筐。
- 普通日子：看窗、听唱片、坐在地毯上，形成安静片段。

玩家看到片段后可以选择：摸摸她、点相关物件继续故事、陪玩、出门，或什么也不做地观察。

### 实现范围

1. 创建 `today-story` 数据模型：`id`、触发条件、起始地点、角色姿态、关联物件、首句台词、可选延续互动、当天是否已看过。
2. 每天根据天气、时段、需求、花园、收藏和前一日记录选择一个片段；不能随机刷新的同一秒反复变化。
3. 首次进入/回到小屋时，让角色进入片段位置与状态；顶部生活线索改为片段的轻提示，而不是资源建议。
4. 关联物件出现轻量、短暂的可发现提示；不得改成常驻箭头或任务标记。
5. 玩家完成片段的延续互动后，只给情绪、动作、环境或小记反馈；奖励可有但不能成为核心。
6. 玩家中断、出门、布置或拖动角色时，片段安全结束，不锁住控制。

### 验收标准

- 冷启动五秒内，玩家能说出雯宝“现在在做什么”。
- 不读任何教程，也能通过角色朝向、物件状态或一句轻提示猜到可继续互动的对象。
- 完成与不完成片段都不惩罚玩家。
- 390px 手机上，片段提示不遮挡角色或主要物件。
- 刷新/离线后片段状态稳定，不因每次进入而突变。

## 5. 后续顺序（不得跳跃）

### 阶段 A：今日片段与小屋首页（进行中）

- 已完成今日片段数据、每日稳定选择器、角色入场、关联物件提示和完成保存。
- 已将顶部生活线索在小屋中升级为叙事提示。
- 首批已实现 7 个片段：听雨、困倦、点心、纪念架、花束回忆、唱片机、地毯发呆；不增加新地点。
- 目标：从“功能展示”变为“值得打开看看”。

### 阶段 B：让空间真正承载故事

- 家具拥有更明确的角色偏好与习惯。
- 花束、纪念、照片不只堆在架子上，而是影响房间细节和角色停留点。
- 咖啡店加入店主关系的轻量变化；街区事件根据已有纪念产生回响。
- 目标：让选择跨天有记忆，而不是只加资源。

### 阶段 C：移动端真机重构和验证

- 用真实 360–430px 手机逐项验证：点角色、拖球、抛球、出门、背包、布置、事件、回忆录。
- 处理安全区、底栏遮挡、双指平移、单手误触、低端性能与减少动态效果。
- 保持“场景中心优先”，任何新 UI 必须从 HUD 预算中扣除。
- 目标：手机体验是主体验，而不是桌面版缩放。

### 阶段 D：内容与架构可维护化

- 将事件、今日片段、旅行路线、资源奖励抽到 `src/game/data/`。
- 建立简单的开发调试面板：切换天气/时间/场景、重置今日事件、注入资源；仅开发环境可见。
- 为存档版本增加迁移函数，不继续散落 `localStorage` 读取逻辑。
- 目标：添加一则故事或一件家具不需要修改多个运行时分支。

### 阶段 E：上线准备

- 真机兼容矩阵、手动回归清单、构建检查自动化。
- PWA 更新策略和明确的缓存策略。
- 评估云存档/账号后端；实时多人不作为当前前置。
- 目标：可稳定部署、可恢复、可持续加内容。

## 6. 现在暂缓的事项

- 新地点、新货币、新大系统。
- 实时多人、房间联机、排行榜。
- 骨骼动画编辑后台和复杂角色资产流水线。
- 家具商店、抽卡、任务面板、签到。
- 大规模美术替换。

它们不是永远不做，而是在“今日片段 + 手机主体验”达标前不做，以免分散开发注意力。

## 7. 每次实现前的快速决策

用下面的问题决定功能是否进入下一轮：

1. 它是否让玩家更容易观察到雯宝正在生活？
2. 它是否必须在场景中发现和操作？
3. 它是否给角色、空间或回忆留下可见变化？
4. 它是否能在手机上单手、低遮挡地完成？
5. 如果没有资源奖励，这件事仍然有情绪或故事价值吗？

五题中少于四题为“是”，不进入开发。

3. 架构

这是母图编辑（image edit），不是 MeinaMix 文生图，也不是锁脸 / 锁姿七组。身份来自锁定母图；服装或角度变化写在编辑提示词里。画布由母图经 VAEEncode 带入，母图与冒烟输出均为 512×768 RGB。图中没有 EmptyLatentImage，也没有 FluxKontextImageScale。

ID类型作用
1LoadImage锁定母图
2UnetLoaderGGUFQ4 编辑 UNet
3CLIPLoaderQwen Image CLIP（type=qwen_image，device=default）
4VAELoaderQwen Image VAE
5LoraLoaderModelOnlyLightning 8 步加速 LoRA，强度 1.0
6ModelSamplingAuraFlowshift 3.0
7CFGNormstrength 1.0
8TextEncodeQwenImageEditPlus正向编辑提示词
9TextEncodeQwenImageEditPlus负向；默认空字符串
10VAEEncode母图 → latent
11KSampler8 步采样
12VAEDecodelatent → 图像
13SaveImage写入官方输出前缀

7. API 约定（给 /api/comfy/draw 对齐用）

Live With You 已核对：开发时「星愿幻阁」走 vite.config.ts 里的 POST /api/comfy/draw，这条代理仍未对齐。本稿核对源码后的现状（不在本任务改它）：

  • 默认底模 meinamix_v12Final.safetensors（可用 COMFY_CHECKPOINT 覆盖）
  • 默认挂 xiaoyan.safetensors，强度 0.8 / 0.8
  • 正向自行拼接 xiaoyan, chibi, ... 五官堆词，再接用户 prompt
  • 图是 CheckpointLoaderSimple + CLIPTextEncode + EmptyLatentImage 512×640，采样 dpmpp_2m / karras
  • 提交到 http://127.0.0.1:8188/prompt，client_id 为 wenbebi-live
  • 轮询 /history/{prompt_id} 的等待上限是 120 秒
  • SaveImage 前缀仍是 wenbao_lora_live
对齐时应当提交本官方 Qwen 图（锁定母图 + 编辑提示词），而不是继续拼旧文生图，也不要把 wenbao_v1 挂到 Qwen 上。tools/generate-comfy-assets.mjs 仍停在同一套旧底模，同属待对齐项，不在本文改。

7.1 提交方式

POST http://127.0.0.1:8188/prompt
Content-Type: application/json

{ "client_id": "<调用方自定>", "prompt": { /* 下方 API 图 */ } }

GET  http://127.0.0.1:8188/history/{prompt_id}
GET  http://127.0.0.1:8188/view?filename={filename}&subfolder={subfolder}&type=output

成功时响应含 prompt_id，且 node_errors 应为空。官方冒烟默认前缀下，filename=wenbao_q4_left34_00001_.png，subfolder=wenbao_qwen_edit_official，type=output。Comfy 会在前缀后追加 _00001_ 这类序号。

等待时间：官方冒烟从提交到成功约 148.78 秒。现有 /api/comfy/draw 的 120 秒上限按这条线会误报超时。对齐时需要加长（建议至少 180–240 秒，并继续轮询 history）。

不建议用 tools/comfy_workflow_to_api.py 直接转这份官方 UI JSON：该转换器依赖节点上的 widget 元数据，而本官方图的加载器主要只写了 widgets_values，转换结果可能丢掉模型名和提示词。已跑通的做法是按官方 JSON 的节点号和 widgets_values 按名称组装 API 图，并以 official_qwen_smoke_prompt.json 里的 prompt 为准。

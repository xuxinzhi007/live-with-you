# 多人共处 · 竖屏场景调研与设计

> **归档（2026-10-29）**：多人已从主线移除，旧移动端保留在 `?legacy` 作为实验入口。
> 当前主线是 V2 单主角小世界，见 [产品宪章 V2](./product-charter.md)；线上没有实时中继时不得假装联机。
>
> 日期：2026-10-20  
> 前提：每个玩家是**独立角色**；通过 **WebSocket** 同步在场与动作；主体验在 **Mobile 竖屏 360–430px**。  
> 对照现网：`MobileLayout` + `scenes.ts`（百分比坐标）+ 本地共处先验（我 + 雯宝代理）。  
> 本文只定场景与同步设计，不假装已接上实时通道。

---

## 1. 要解决的问题

当前本地先验把「对方」做成雯宝宠物代理，只能验证动词。真多人要满足：

1. **身份独立**：每个玩家有自己的 `playerId`、名字、外观、存档侧身份；不是共用一只宠物。  
2. **动作可知**：A 做「打招呼 / 递点心」，B 的屏幕上能看见对应动画与结果。  
3. **竖屏可读**：两个人同屏时，角色、家具、共处入口都不被挤成一团，也不靠横滑条抢底栏。

打开时机仍是「一起玩的一局会话」，不是每日联机大厅。

---

## 2. 调研结论（竖屏多人在场）

| 来源 | 可借 | 不借 |
| --- | --- | --- |
| 旅行青蛙 / 月兔 | 世界即界面；关系反馈情境出现 | 单角色观察当主循环 |
| 口袋营地 | 底栏少项；互动时 HUD 让路 | 红点催促、多入口轰炸 |
| Honk（即时陪伴） | **在场感**：进入/离开/分心要有可见信号；相对坐标点赞跨屏一致 | 做成纯聊天 App |
| BlueJeans Spaces 移动端 | 竖屏 FOV 极窄，不能指望「看到整间房」 | 把桌面大世界原样塞进竖屏 |
| 同机双人分屏竞技 | 颜色身份清晰 | **对坐分屏 / 旋转 180°**——雯宝是异步同世界，不是抢一台手机 |

**归纳三条硬规则**

1. **同世界、同朝向、双设备**：两人各拿手机，看同一房间的两个独立角色，不是分屏对战。  
2. **竖屏只保证「两人关系可读」**：脸、相对位置、正在做什么；不保证家具全图一览无余。  
3. **在场 > 移动精度**：第一版同步「在哪个场景 + 站位槽 + 当前动作」，不必先做自由走位物理同步。

## 3. 竖屏场景构图（核心）

验收画幅：**390 × 844**，安全区含底部手势条。

### 3.1 空间分层（从上到下）

```text
┌─────────────────────────┐  ~8%   顶栏：我的名 / 对方在场点 / 资源一颗
│  我 · 在线●对方          │
├─────────────────────────┤  ~10%  地点条（可缩成当前地点+切换）
│ 小屋 阳台 街区 咖啡馆     │
├─────────────────────────┤
│                         │
│     墙面家具带           │  ~45–55%  「舞台」：两人站位 + 关键家具
│      [我]    [对方]      │         角色脚底约在舞台下缘
│                         │
├─────────────────────────┤  ~12%   共处入口（单颗「一起做」）
│        ( 一起做 )        │
├─────────────────────────┤  ~12%   底栏 陪伴|收藏|手账|聊聊
└─────────────────────────┘  + safe-area
```

- **舞台高度优先于地点条**：地点多时可收成「小屋 ▾」。  
- **两人默认肩并肩站舞台中央偏下**，脚底对齐同一地面线（现网 `bottom ~10–14%` 量级），避免一前一后造成「谁在前」的遮挡战争。  
- **家具**：竖屏只保证「窗外 / 床 / 门」等 3–5 个大触点可读；过密家具改为点地点后再进特写，或降低非关键家具透明度。

### 3.2 双人站位槽（推荐，替代自由坐标同步）

自由 `x,y` 同步在弱网竖屏上容易抖、遮挡、对不齐。第一版用**场景内站位槽**：

| 槽 | 含义 | 竖屏百分比（建议起点） |
| --- | --- | --- |
| `L` | 偏左（默认：本地玩家） | left ≈ 28%, bottom ≈ 12% |
| `R` | 偏右（默认：远端玩家） | left ≈ 62%, bottom ≈ 12% |
| `C` | 中间（共处动作时常临时占用） | left ≈ 45%, bottom ≈ 12% |
| `near:{furnitureId}` | 走到某家具旁（递点心/一起看窗） | 由家具锚点推导 |

规则：

- 进入同一 `sceneId` 时，按 `playerId` 稳定哈希或「房主左 / 访客右」分配 L/R，避免两人抢同一槽。  
- 共处动词开始：两人 tween 到相关槽（如一起坐 → 都靠 `near:armchair` 的左右子槽）。  
- **不同步连续位移**，只同步「目标槽 + 动作 id + 开始时间」。

### 3.3 身份可读（独立角色）

每个角色身上始终有：

- 短名或「我」标签（自己） / 对方昵称（远端）  
- 可选色点（两人各一色，贯穿气泡与在场点）  
- 外观来自**各自**的 `lookId` / 立绘，禁止共用一只宠物精灵当对方

在场状态（顶栏或头旁小点）：

| 状态 | 表现 |
| --- | --- |
| `online` | 实心点 |
| `away` | 虚线点（应用在后台） |
| `offline` | 灰点；角色可半透明「留下的影子」或收起 |

参考 Honk：进入/离开要有短动画或一句气泡，让「你来了」可感知。

### 3.4 交互热区（竖屏拇指）

| 操作 | 热区 | 说明 |
| --- | --- | --- |
| 摸对方 / 看对方 | 点对方立绘 | 本地立刻播预测动画，同时发 WS 事件 |
| 摸自己 | 点自己立绘 | 仅本地表情，或同步「自嗨」类低优先级事件 |
| 共处动词 | 「一起做」→ 3×2 面板 | **禁止**常驻横滑条压底栏（已踩过坑） |
| 家具 | 点家具 | 若需对方一起：先选共处动词再自动走槽 |
| 切换地点 | 顶/地点条 | 发起 `scene.propose`；对方同意或自动跟随（见同步） |

触控目标 ≥ 44px；共处面板打开时遮罩可点关，底栏仍可切走。

## 4. WebSocket 同步设计（动作可知）

### 4.1 房间模型

```text
Room { roomId, sceneId, members[playerId] }
Member { playerId, displayName, look, slot, action, actionStartedAt, presence }
```

- 一局「一起玩」= 一个 Room（可用情侣固定 `coupleId` 或临时邀请码）。  
- 权威：服务器校验事件；客户端**乐观预测**本地动画，以服务器回放为准纠偏。

### 4.2 事件（第一版够用）

| 事件 | 载荷 | 双方表现 |
| --- | --- | --- |
| `presence.join` | player profile | 入场动画 +「来了」 |
| `presence.leave` / `away` | playerId, reason | 挥手/虚线点 |
| `scene.enter` | sceneId, slot | 切场景、落到槽 |
| `action.self` | actionId（挥手/坐下等单人） | 对方看见你的动作 |
| `action.coplay.invite` | coplayId, from, to | 对方弹出「一起坐下？」可忽略 |
| `action.coplay.start` | coplayId, participants, slots | 双方播同一套共处动画 |
| `action.coplay.cancel` | id | 收回 |
| `trace.write` | journal 短句 | 写入双方可见留痕（可延后） |

共处动词建议：**邀请制**（A 发起 → B 接受）避免 B 正在点家具时被强制拉走；极短动作（打招呼）可允许单向广播无需接受。

### 4.3 时间与弱网

- 所有动画用 `serverTime` + `duration`；客户端 `localStart = now + (serverTime - estimatedOffset)`。  
- 超时未收到 `ack`：本地保留预测，标「可能不同步」；不打断可玩性。  
- 断线：角色变 `away`，可继续单人摸家具；重连后 `state.snapshot` 全量对齐。

### 4.4 与现网代码的映射

| 现网 | 多人改造 |
| --- | --- |
| `GameState.player` | 保留为**本地玩家**；新增 `peers: Record<playerId, PeerState>` |
| `pet`（雯宝） | 降级为可选 NPC / 或移除出共处主路径；**对方不再复用 pet** |
| `applyCoplay` | 拆成：本地预测 + `action.coplay.*` 发送；回放走同一动画表 `coplay-actions.ts` |
| `scenes.ts` 百分比 | 为每家具增加 `anchors: { L, R }` 供走槽 |
| `MobileLayout` | 渲染 `local + peers`；在场点；邀请条 |

后端：Frame 已提 `moe_social` 暂无实时通道 → 需**新增 WS 网关**（或独立小服务），REST 只负责房间创建/鉴权。

## 5. 竖屏专属风险与对策

| 风险 | 对策 |
| --- | --- |
| 两人 + 家具 = 糊成一团 | 站位槽 + 共处时淡化非相关家具 |
| 顶地点条 + 底栏 + 共处条三重压迫 | 共处仅单入口；地点可折叠 |
| 对方动作看不见 | 动作必换姿势/短位移/气泡，禁止「只加 journal」 |
| 两人同时点不同家具 | 邀请制共处；单人动作互不打断 |
| 一方横屏一方竖屏 | 协议用槽位与百分比，禁止用绝对像素 |
| 「一起做」横滑丑且挡操作 | 已否决；保持面板 |

## 6. 推荐落地切片

### Slice 0（已有）
本地：独立「我」+ 雯宝代理 + 共处动词面板。用于验动词列表。

### Slice 1 — 数据与竖屏舞台（可先不接真 WS）
1. `PeerState` + 双独立外观渲染（第二个角色也走 `player-looks`，可用第二个本地测试号）。  
2. 场景站位槽 + 家具 anchors。  
3. 顶栏在场点 UI。  
4. 用 **MockTransport**（内存/BroadcastChannel）模拟双端，同机两个浏览器标签验竖屏。

### Slice 2 — WebSocket
1. 房间加入 / presence / scene / action 事件。  
2. 共处邀请条（竖屏底部轻条，不盖角色脸）。  
3. 断线 away + snapshot 重连。

### Slice 3 — 打磨
动作 juice、留痕同步、对方角色创建流、弱网纠偏。

## 7. 验收（390 竖屏）

1. 两人同房时，**不看名字也能分清谁是谁**（外形+色+站位）。  
2. A 点「打招呼」，B 在 1s 内看到挥手类反馈。  
3. 打开「一起做」面板时，角色头部仍可见或仅短暂遮罩。  
4. 无横滑共处条；底栏不被第二常驻条叠死。  
5. 一方切后台，另一方看到 away，不卡死。

---

## 8. 一句话决策

**竖屏多人共处 = 同世界双独立角色 + 站位槽同步动作（WebSocket）+ 极简 HUD；先保证「看见对方在做什么」，再考虑自由走位与大世界。**

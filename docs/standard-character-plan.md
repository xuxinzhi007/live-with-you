# 标准比例角色底模方案（v2）

> 状态：**设计定稿，未改代码**。等你确认第 9 节后进入实现。
> 取代：[character-rig-design.md](./character-rig-design.md) 中“1.87 头身”的比例基准；
> 画布、槽位、容差、流水线仍沿用该文。
> 日期：2026-10-29

---

## 0. 结论

1. **采用标准比例，目标 5.0 头身（可参数化到 6.0）。**
2. **不在现有 chibi 图上“缩头”。** 那张图是单层平面插画：裙子盖住腿、手臂压住身体，
   没有可分离的底层；缩头后脸只剩约 52px，而且身体仍然没有腰、胯、腿的结构。
3. 做法是 **新底模 + 部件 + 合成 + 场景重标定**：
   - 新底模：5 头身、A-pose、透明底、760×760、脚底 748、中心 380。
   - 部件：头 / 脸 / 发 / 身体 / 手臂 / 腿 / 服装，按姿势家族（stand / sit / lie）出变体。
   - 合成：输出仍是现有整帧格式，渲染层 `pickFrame()` 不用改。
   - 场景：`PLAYER_STAND_H` 300 → 333，家具高度 ×1.11，房间宽度约 980 → 1120。
4. 现有白色 chibi 保留为 `original`，新皮肤 id `standard`；
   **新档默认 `standard`**，旧档迁移策略见第 7 节。

一句话：**“标准比例”是一次新底模 + 场景重标定，不是一次 resize。**

---

## 1. 为什么不能直接缩头

### 1.1 现有立绘不是可拆的

- 白色 `original` 是单层平面插画：裙子从胸到脚是一整块，腿只露出脚踝以下；
- 手臂与袖子压住裙侧，头发压住肩背；
- 没有任何“底层身体”的像素，切掉裙子就是洞。

所以“把头缩小、身体拉长”没有可操作的对象：要么重画，要么接受穿帮。

### 1.2 屏幕数学（390 × 844 实测）

舞台高度 **780px**（844 − 64 底栏；顶栏是 absolute 浮层，不占 stage 高度）。
世界高 1000，比例 **0.78px / 世界单位**。脚底 world 880 → screen **686.4px**。

现状：

| 皮肤 | 帧内头高 | 头身比 | 屏上身体 | 屏上头 | 占舞台 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `original` | 386 / 720 | **1.87** | 234px | **125px** | 30.0% |
| `maid` | 345 / 712 | **2.06** | 234px | 113px | 30.0% |

目标（头部保持 52px，即“脸可读”的下限）：

| 方案 | 头身 | 身体 world | 身体 px | 占舞台 | 头 px | 家具倍率 | 房间宽 | 风险 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| S1 | 4.5 | 300 | 234 | 30.0% | 52 | ×1.00 | 980 | 低（仍偏 Q） |
| **S2（推荐第一版）** | **5.0** | **333** | **260** | **33.3%** | **52** | **×1.11** | **~1120** | 中 |
| S3 | 6.0 | 400 | 312 | 40.0% | 52 | ×1.33 | ~1400 | 高（重排房间） |

- 头 52px 是“五官可读”的实测下限；眼高约 8px，必须用更干净、更大的眼睛来补偿。
- S3 更接近“标准”，但首页宽度 980 放不下 ×1.33 的家具（当前家具宽度总和已 964），
  必须把房间加宽到 ~1400 并重排所有 x 坐标；这是第二个项目。
- S2 只需把房间加宽到 ~1120，家具宽度总和约 1070，改动可控。
- 代码里把目标头数做成常量，S2 → S3 只改一个数 + 重排，不重写逻辑。

### 1.3 脸变小是最大的代价

头部从 125px 降到 52px，是 **2.4 倍**的线性缩小。当前脸部的细节（睫毛、腮红、嘴形）
在 52px 下会糊。验收必须先过“52px 脸”这一关：

- 正面、100% 缩放、390×844 截图；
- 三个表情（中性 / 笑 / 困）在同一尺寸下必须能区分；
- 不能靠“放大看”才认得出。

**如果 52px 脸不可读，标准比例就不成立**，应回到 S1 或保留 chibi。

**已测结果**（`face-readability-390.png`，用现有 chibi 头裁切）：

| 头高 | 三表情可区分 | 五官细节 | 判断 |
| ---: | --- | --- | --- |
| 125px | 能 | 完整 | 现状 |
| **52px** | **勉强能** | **只剩轮廓色块** | 过线，但代价明显 |
| 39px | 开始分不清 | 没了 | 不可用 |

结论：52px 过了「能区分表情」，但**没过「五官可读」**。现有 chibi 的眼睛偏写实，
一缩就糊；新底模必须用更简洁、更大的眼睛来补偿（印证本节开头那句）。
本结果用旧头裁切，新底模仍需单独过这一关。

## 4. 生成流水线

### 4.1 顺序（不能反）

1. **底模**：5 头身 mannequin（无服装、简单内衣、A-pose），正面、平视、纯色底。
2. **三套身体**：stand / sit / lie，各自完整无遮挡。
3. **服装**：先做一套基础连衣裙，覆盖三套身体。
4. **头发**：后发 → 前发，分两件。
5. **脸**：单独一件，先做中性 / 笑 / 困。
6. **配饰**：最后，可选。

### 4.2 提示词骨架

```text
Single full-body character reference, front view, orthographic, no perspective,
standing in a relaxed A-pose with arms 20 degrees away from the body, feet together,
feet at the very bottom edge, perfectly centered, head-to-body ratio exactly {heads} heads
(5.0 default; head height = body height / {heads}).
Plain flat colors, no shading gradient, no cast shadow, no ambient occlusion,
clean closed silhouette, crisp edges, consistent line weight,
plain solid #00FF00 background, no text, no watermark, no border.
Style: cozy storybook / soft anime, same face design as the reference image.
{slot} layer only: {slot description}.
Pose family: {pose}  (stand / sit / lie).
Palette locked to: {palette}.
```

负面提示：

```text
chibi, 2-head-tall, super-deformed, huge head, tiny body,
three-quarter view, side view, perspective, foreshortening,
cropped feet, extra fingers, extra limbs, cast shadow, gradient background,
blurry, jpeg artifacts, text, watermark
```

### 4.3 自动处理

复用 `tools/build-character-assets.py`：flood-fill 抠图 → 去白边 → trim → 按同一基线缩放。

新增 `tools/character/`：

| 脚本 | 作用 |
| --- | --- |
| `make-spec.py` | 生成 `spec.json` + 对位模板 + 骨架图 |
| `verify-part.py` | 校验单件：高度/脚底/中心/头身比/主色/洞/白边 |
| `compose.py` | 按 `character.json` 合成整帧 |
| `prompt.md` | 从 spec 拼提示词 |

### 4.4 校验指标（v2）

| 指标 | 容差 | 失败处理 |
| --- | --- | --- |
| 站立可见高 | 720 ± 7 | 重新缩放 |
| 脚底 | 748 ± 0 | 重新对齐 |
| 水平中心 | 380 ± 2 | 重新对齐 |
| 头身比 | 5.0 ± 0.2 | 退回重画 |
| 头部高度 | 144 ± 6 px | 退回重画 |
| 主色 ΔE | ≤ 6 | 调色或退回 |
| 站姿剪影 IoU | ≥ 0.90 | 退回重画 |
| 底层透明洞 | 0 | 必须补画 |
| 边缘近白像素 | < 3% | 重新抠图 |

## 5. 场景重标定（S2）

> **适用条件**：本节只在「**5.0 头身 + 家具随 S3 一起重标定**」这个分支成立。
> §9 选「先只换角色、家具不动」时整节作废；选 4.5 / 6.0 时所有绝对值需按新 `standHeight` 重算。

### 5.1 全局常量

| 常量 | 现在 | S2 | 说明 |
| --- | ---: | ---: | --- |
| `PLAYER_STAND_H` | 300 | 333 | 或改成 per-skin `standHeight` |
| 家具高度倍率 | ×1.00 | ×1.11 | 门/床/桌/椅/架/吧台 |
| 房间宽 home | 980 | ~1120 | 家具宽度总和约 1070 |
| 房间宽 garden | 960 | ~1080 | |
| 房间宽 street | 1180 | ~1300 | |
| 走位带 | 760–884 | 760–884 | 不变 |
| 地平线 | 640 | 640 | 不变 |

### 5.2 家具逐个定标（S2，×1.11）

| 物件 | 现在 h | S2 h | 与身高比（333） |
| --- | ---: | ---: | ---: |
| 门 | 340 | 378 | 1.13 |
| 床 | 240 | 267 | 0.80 |
| 书桌 | 210 | 233 | 0.70 |
| 收藏架 | 300 | 333 | 1.00 |
| 长椅 | 140 | 156 | 0.47 |
| 喷泉 | 250 | 278 | 0.83 |
| 花摊 | 330 | 367 | 1.10 |
| 大树 | 520 | 578（或 ×1.15=598） | 1.73 |

宽度不要盲目 ×1.11：床/吧台可以 ×1.15，门 ×1.10，树 ×1.15；
每件新素材按真实宽高比画，不再用正方形 SVG 塞进盒子。

### 5.3 需要重排的坐标

- `rooms.ts` 的 `x` 必须重排：当前 home 五件主要家具宽度总和 964，已接近 980；
  ×1.11 后 1070，必须加宽房间并重新分配 x，避免门与床/桌重叠。
- `footprint` 的 x0/x1/y0/y1 随 w/h 调整；`approach` 的 y 可能 +10~20。
- `camera` / `MAX_CAM` 自动跟随 `worldW - viewW`，不用手改。
- 背景图（`tools/build-scene-assets.py`）按新 `worldW` 重出；墙/地板分界不变。

### 5.4 验收

- 三线对齐：角色脚底、家具底边、地板接触线误差 ≤ 2px。
- 关键家具 0.6–1.2× 身高（门/窗按建筑尺度 1.1–1.5×）。
- 390×844 截图：角色不被 HUD 挡、不被家具挡、门口可走。
- 点击热区与可见边缘误差 ≤ 8px。
- 旧 chibi 皮肤仍可切换；若家具按 S2 放大，chibi 会显矮，需要决定是否保留。

## 6. 渲染接入

### 6.1 新增 `standHeight`

`CharacterSkinMetrics` 增加：

```ts
standHeight: number; // 世界单位；original 300 / standard 333
```

`WorldView` 里两处 `PLAYER_STAND_H`（缩放与点角色宽度）改为 `this.skin.metrics.standHeight`。
`PLAYER_STAND_H` 保留为默认值，避免大改。

### 6.2 合成输出

- build 期：预设 look 合成成整帧，写进 `assets/characters/<skin>/`；
- run 期：玩家改 look → 合成一次 → `RenderTexture` 缓存；
- `pickFrame()` 只认整帧，不需要知道部件。

### 6.3 动作

| 动作 | 实现 |
| --- | --- |
| 呼吸 | 整体缩放 + 抬升（已有 4 帧烘焙；部件化后可程序化） |
| 走路 | 手臂/腿绕 pivot 正弦旋转（`styles.css` 已有 keyframes 可移植） |
| 坐下 / 躺下 | 切换姿势家族的部件变体，零旋转 |
| 短交互 | `react` 帧或整体缩放 |
| reduced-motion | 只出静帧，不旋转、不缩放 |

## 7. 存档与默认皮肤

- 新增 `CharacterSkinId = "original" | "maid" | "standard"`。
- `DEFAULT_CHARACTER_SKIN` 改为 `"standard"`（仅影响**新档**）。
- 旧档已有 `world.skin: "original"` → 保持 chibi，不静默改外观。
- 「更多 → 角色外观」三项：标准 / 白色 Q 版 / 小鲸鱼。
- `normalizeWorldState`：缺失或非法 → `standard`；旧档缺 `skin` 时也回 `standard`。
- 可选一次性迁移（需你确认）：
  - 加 `world.skinVersion`；缺失且 `skin === "original"` → 自动升 `standard` 并写 2。
  - 优点：你自己打开就是新外观；缺点：老玩家/对象的外观会变。
  - 默认建议：**不自动迁移**，在「更多」里提供一键切换；验收截图用 `?skin=standard` 强制。

## 8. 分期

| 阶段 | 内容 | 验收 | 回滚 |
| --- | --- | --- | --- |

## 9. 需要你拍板

1. **目标头身**：**5.0（推荐第一版）** / 6.0（更标准，但房间要重排到 ~1400） / 4.5（最保守）。
2. **旧档**：保持 chibi，手动切新外观（推荐） / 自动升级到 standard（外观会变）。
3. **chibi 去留**：保留为「Q 版」皮肤（推荐） / 从选择器移除但存档继续可用。
4. **场景重标定**：随 S3 一次做完（推荐） / 先只换角色、家具不动（会显大）。

## 10. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 52px 脸不可读 | 标准比例失败 | S1 先做脸测试；不行回 4.5 头/保留 chibi |
| AI 一致性差 | 每张脸不同 | 固定种子 + 同一 mannequin 参考 + 调色板校验 + 人工修 |
| 接缝/白边 | 穿帮 | 10–15% 重叠 + 去白边 + 人工修 |
| 家具重排破坏走位 | 卡住/穿模 | 用 `canStand` 单测扫全走位带；390×844 截图 |
| 房间加宽后背景重画 | 工期 | 背景用现有生成脚本按新 `worldW` 重出，不改风格 |
| chibi 与新家具比例冲突 | 显矮 | chibi 作为 Q 版明确标注；或家具只按 standard 定标 |

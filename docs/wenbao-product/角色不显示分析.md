# 角色不显示：原因分析

- 日期：2026-11-13 01:53（Asia/Shanghai）
- 环境：用户 Windows 本机 ZhuanZ，工程 `C:\Users\ZhuanZ1\Desktop\wenbebi`，分支 `featurle/xinzhi_feat`
- 负责：Live With You（客户端与舞台接线）。本文只分析、给出修复方案，**尚未改代码**。

## 结论

角色不显示的主因是：**客户端把立绘 URL 全部解析到局域网资源库 `http://192.168.124.77:8788`，而本机此刻访问该地址会连接超时；加载失败时又没有回退到仓库里已经存在的本地文件。**

这不是出图问题（官方 Qwen 线用户已过目、认为没有问题），也不是四层开关被关掉造成的。本地皮肤帧齐全。

## 核实记录

1. **资源库不可达。** 2026-11-13 01:53 从 ZhuanZ 执行 `curl` 访问 `http://192.168.124.77:8788/`，约 5 秒后超时，退出码 28（Connection timed out），HTTP 状态为 000。
2. **URL 全部指向这台库。** `src/mobile/world/remote-assets.ts` 中 `DEFAULT_ASSET_BASE_URL` 为 `http://192.168.124.77:8788`。`resolveAsset()` 在路径能映射时只返回 `${base}/files/{cat}/{name}`，没有「加载失败再用本地路径」的分支。注释和 `docs/current-state-and-next.md` 写过「库不可用则回退」，但那只在环境变量被设为空时成立，不是运行时回退。
3. **默认立绘走皮肤帧，也会被解析走。** 默认衣服 `dress-snow-white` 的图是 `assets/characters/original/idle.webp`（不是 Comfy 的 `dress-*.png`）。`skins.ts` 对 idle / breathe / react 都做了 `resolveAsset`，实际请求变成：
   `http://192.168.124.77:8788/files/base/original-idle.webp`
   以及对应的 `original-breathe-1.webp` 等。这些请求会一直等到超时，`<img>` 失败，舞台空白。
4. **本地文件是齐的。** `public/assets/characters/original/` 下有 `idle.webp`、`breathe-1`–`4.webp`、`react.webp`、`walk-*`、`sit.webp`、`sleep.webp`、`avatar.webp`；`maid` 皮肤同样齐全。只要回退到相对路径，Vite 可以从 `public/` 直接提供。
5. **四层关闭不是原因。** 工作副本里 `PHASE1_LAYERED_OUTFIT_IDS = []`（相对已提交的 `["dress-snow-white"]`，尚未提交）。关闭后走皮肤帧或整身抠图回退，设计如此。本地皮肤帧如果 URL 正确，角色应当显示。
6. **开发代理仍走旧 MeinaMix**（`vite.config.ts` 的 `/api/comfy/draw`）会造成「幻阁里出的是旧脸」，但不会让大厅默认立绘消失。这是另一项对齐工作，等主人点头再改，并需向 comfyui 要官方 API。

## 建议修复（未实施）

优先级 P0，只动客户端资源解析，不动出图、四层和入库。

1. **图片 `onerror` 回退：** 舞台、封面、头像上的 `<img>` 在远端失败时，改用未经 `resolveAsset` 的本地相对路径。
2. **启动探活：** 对 `8788` 做短超时（例如 1–2 秒）探测；失败则本场会话默认全部走本地，避免每张图都卡在连接超时上。
3. **不要删 `public/assets`。** 它是正式回退源，不是临时备份。
4. **可选：** 若 localStorage 里存了已失效的定制图 URL，失效时回到默认皮肤帧，不要一直空着。

验收：在访问不到 `192.168.124.77:8788` 时，打开封面和大厅，数秒内能看到雯宝。库恢复后仍可优先走远端。

改代码前等主人点头。

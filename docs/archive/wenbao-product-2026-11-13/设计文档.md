# 雯宝 设计文档

- 版本：2026-11-13（Asia/Shanghai）
- 配合：[PRD.md](./PRD.md)、[架构文档.md](./架构文档.md)
- 范围：现行 WorldApp 体验，以及官方出图切到 Qwen 之后，客户端应当怎样表现

> 本文是客户端与舞台体验的设计说明，由 Live With You 出具。官方出图交互的 Comfy 细节见 comfyui 文档；资产与训练门禁见小燕资产管线文档。

## 1. 设计原则

1. **先看见她。** 任何资源策略都不能让舞台在打开时是空的。局域网图库是加速和统一管理，不是显示的唯一来源。
2. **装扮变化要立刻反映在立绘上。** 界面首先是试衣镜和舞台，不是任务清单。
3. **正式出图和开发预览用同一套身份标准。** 母图是 `Wenbao_redraw_00001_.png`：白 T、白短裤、白鞋，短黑发齐刘海、棕眼、浅笑。不要锁成 Q 版比例。
4. **少即是多的提示词。** 身份交给母图（以及将来可能的 LoRA 触发词 `wenbao`），提示词只描述这张要改的衣服、姿势、构图。

## 2. 信息架构

```
封面 title
  └─ 大厅 lobby ── 共享舞台（雯宝立绘）
        ├─ 换装 wardrobe     五槽衣橱 + 试衣镜
        ├─ 骨骼 rig          关节标定（工坊）
        ├─ 闯关 stages       主题评级
        ├─ 星愿幻阁 pavilion 抽卡 / 实时生图工坊
        ├─ 图鉴 codex        收集与羁绊
        └─ 密语 chat         陪伴对话（Ollama，失败则离线回复）
```

底栏导航 + 顶栏资源（魅力、礼券）。竖屏、可单手。不把常驻数值仪表盘压过立绘。

默认装扮：`dress-snow-white`（初雪白茶连衣裙）+ 雏菊发夹 + 茶杯 + 晨风光环 + 第一杯茶心境卡。

## 3. 舞台表现：三条显示路径

舞台只有一个视觉目标：画面中央站着雯宝。实现上有三条路径，同一时间只走一条。

| 路径 | 何时用 | 画面构成 | 现状 |
| --- | --- | --- | --- |
| A. 皮肤帧 | 当前衣服不是 Comfy 整身图，且没有用户定制图。默认的 `dress-snow-white` 走这条 | `idle` / 4 张 `breathe` 循环，点按时切 `react` | 本地文件齐全，但 URL 被解析到 8788，库宕则空白 |
| B. 整身抠图 + 假切片 | Comfy 的 `assets/nikki/dress-*` 或不透明定制图 | `loadCutoutImage` 洪水填充 → 760 画布 → 按骨骼 clip-path 切 6 片 | 依赖原图加载成功；抠图失败会把原 URL 再填回去 |
| C. 真四层纸娃娃 | `PHASE1_LAYERED_OUTFIT_IDS` 包含该衣服，且四张透明件都能探测到 | 自下而上 body → dress → head → arms-front | 开关为空，有意关闭；图库四张尚未过门 |

配件（头饰、手持、光环）以 SVG 可穿戴叠加挂在骨骼锚点上，三条路径共用。

**设计要求：** 路径 A 在远端失败时必须回到本地相对路径，不能空等。路径 B 在抠图未完成时，可以继续显示上一套已抠好的图，但第一次打开不能长期空白——应有本地占位立绘或加载中的明确骨架，而不是什么都不出。路径 C 未过门前不要自动探测整身图当分层，以免错层。

## 4. 角色与服装视觉

- **身份**只由主图锁定，不靠把「短发、刘海、棕眼」写进每句提示词，也不靠 Q 版身材去「统一风格」。
- **默认衣服**只在主图和主图 caption 上写全：白 T、白短裤、白鞋、全身正站、简单背景。
- 其他训练/衍生图的 caption：`wenbao` 打头，只写该图真实的衣服和姿势。`mother_05`（棕发、灰底）已隔离，不进第一组。
- 换装体验上，当前衣橱里的「初雪白茶」「暮色蔷薇」等仍是产品套装名；它们的立绘来源（旧皮肤帧或旧 Comfy 整身）与「官方新出图」要逐步用 Qwen 母图线替换，但不能在替换完成前抽空舞台。

## 5. 官方出图交互（现行）

用户侧已经确认：按现有新流程出图没有问题。设计上把这条线定为**唯一正式出图入口**：

1. 打开 `Qwen_Image_Edit_2509_Q4_官方出图.json`
2. 母图固定为 `Wenbao_redraw_00001_.png`
3. 用提示词描述要改的角度、衣服或动作
4. 人工对照母图：五官能对上才收下；漂了不加

这是「以图编辑图」而不是「从零文生图」。好处是身份锚在已确认的一张脸上，符合「一张主图衍生多角度」的路线。开发用的「星愿幻阁」实时按钮，在对齐之前不要表现成正式出品按钮。

## 6. 实时工坊对齐后的界面（待授权，仅设计预留）

- 用户仍在幻阁里输入短提示（要一件衣服或一个姿势）。
- 后端不再自拼 MeinaMix 图，而是把母图和提示词交给官方 Qwen 工作流。
- 生成中：明确「正在按官方线出图」，超时或失败给能看懂的原因（Comfy 未开、显存、模型未齐），不要只说 8188 没启动。
- 成功后：仍走现有抠图并对齐 760 骨骼画布，再绑定到当前单品。不自动入库、不自动开四层。

## 7. 动效与骨骼

- 待机：轻微呼吸（位移或缩放），不要用会把角色移出画框的幅度。
- 点按 / 换装：短反馈，然后回到 idle。
- 骨骼工坊：1:1 正方形坐标系，百分比锚点随舞台放大同步。最新提交已用关键帧动画替代硬编码正弦波，设计上动画不能成为「看不见角色」的原因——角色不可见应先查资源 URL，而不是先改动画。

## 8. 专业依据（设计侧）

- **桌面宠物与陪伴产品**的底线是本地可显示。Shimeji、常见 Live2D 桌宠都把默认立绘打进客户端；远端图库只作更新通道。雯宝已有完整本地皮肤帧，却把唯一 URL 指到局域网上，违反了这条底线，也违反了产品宪章「打开数秒内看到雯宝」。
- **纸娃娃换装**的行业做法（暖暖等）是：统一画布和脚底锚点，层之间必须是透明切件，不能拿整身图冒充分层。所以四层开关现在关闭是正确的，不能为了「有图」就打开未过门的整身件。
- **身份锁定**上，在角色 LoRA 尚未锁住脸的前提下，用已确认母图做 Image Edit（Qwen-Image-Edit）比继续加 ControlNet / 提高 IPAdapter 更合理。提示词负责变量，母图负责常量。这与当前正式线一致。

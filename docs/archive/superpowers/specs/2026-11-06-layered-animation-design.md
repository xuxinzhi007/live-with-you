# 分层纸娃娃与动作状态机（第一期）

日期：2026-11-06  
项目：雯宝 / live-with-you（本地分支 `featurle/xinzhi_feat`）  
状态：已与产品方向对齐，待实现

## 目标

当前点击、换装主要是切换整张立绘，角色像幻灯片。交叉淡入不能解决这个痛点。第一期用真正的透明分层件，加上连续的骨骼/状态机动作，让一个造型先「活起来」。

不在第一期范围内：Live2D / Cubism 导出、Spine、Blender 或 VRoid、走路与坐下循环、新的整身生成批次。

## 验收

- 同一造型持续呼吸，不再硬切 4 张呼吸帧。
- 点击角色播放一段短反应，结束后回到待机。
- 换一件衣服时，只换衣服层（短淡入淡出 + 短整理姿态），整个人不闪成另一张整图。
- 分层图缺失时，回退到现有整身图 + 运行时抠图，游戏仍可运行。

## 分层约定

画布与现有角色规格一致：760×760，脚底约 y=748，水平居中。所有层使用同一 OpenPose 锁定站姿，由现有小燕 LoRA 生成，必须带透明通道。

第一套四层：

| 层 | 职责 | 建议文件名 |
| --- | --- | --- |
| body | 身体底模（不含头、前景臂、外套装） | `base/original-body.png` |
| dress | 一件衣服 | `dress/<outfit-id>.png` |
| head | 头与刘海 | `base/original-head.png` |
| arms-front | 前景手臂 | `base/original-arms-front.png` |

衣服以后按件替换 dress 层；头与手臂尽量复用。资源写入小主机分类库，并由 `remote-assets.ts` / `manifest.json` 解析。本地 `public/assets` 整身图先保留，作为回退，不在本期删除。

出图要求：同姿势、分图层、透明底。不新增没有清单的零散图。

## 渲染

舞台用多层叠图替代单张角色 `img`，也替代现在把一张图假切成六块 CSS 的做法。叠放顺序自下而上：body → dress → head → arms-front。目录卡、心境卡仍可使用现有卡面图；舞台真相是这些透明层。

远端地址不可用或某层 404 时：该造型回退到当前整身路径（`VITE_ASSET_BASE_URL` 为空则走仓库原路径；本期不必做通用的图片 onerror 框架，但分层加载失败必须有明确回退）。

## 动作状态机

三个状态，同一时间只播一段，新输入打断旧输入：

1. `idle`：轻微呼吸（各层一起做轻微缩放，或现有骨骼的起伏），循环。
2. `react`：点击角色触发，短反应后回到 `idle`。
3. `equip`：更换 dress 层时，衣服短淡入淡出，同时播一段整理衣服的短姿态，然后回到 `idle`。

不在第一期加入走、坐、睡。现有 `skeleton-system` 的插槽与姿态计算继续作为层定位基础；SVG 配件叠层规则保持「舞台以 SVG/层为准，目录图可以是 PNG 预览」。

## 与现有系统的关系

- 入口仍是 `WorldApp`。
- `useWorldGame` 继续只向外提供界面需要的状态；换装动作由舞台状态机处理，不复活旧的浇花/逛街接口。
- `paper-doll-rig` 继续负责配件叠层与旧抠图回退；骨骼插槽仍以 `skeleton-system` 为唯一锚点模型。
- 三张旧的不透明 Comfy 套装（512×640）不在本期重制为 760 分层；新分层件按上表另存。读不到新分层时走旧抠图。

## 明确不做

- 不把未分层的整身 PNG 直接送进 Live2D 或 Spine。
- 不重做三维角色。
- 不把 Live2D 运行时或 Pixi 为了本期重新加回来。
- 同一套分层以后可以再导出到 Cubism 免费版，作为后续升级，不是本期交付。

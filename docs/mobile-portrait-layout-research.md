# 竖屏移动端游戏布局调研（雯宝）

> 状态：已按第 4 节三态落地代码，待真机 390 × 844 再验收键盘与挡门。  
> 对照：[产品宪章](./product-charter.md)、[游戏方向](./game-direction.md)  
> 验收画幅：390 × 844 竖屏，单手拇指。

## 1. 这类游戏在解决什么问题

雯宝不是动作游戏，不需要摇杆和技能键。它和《月兔奥德赛》《旅行青蛙》《口袋营地》同一类：**竖屏、单手、短会话、世界本身就是界面。**

竖屏手机的物理限制是固定的：

- 可用高度会被浏览器地址栏、底部手势条吃掉一截。
- 单手时，拇指热区在屏幕下三分之一；顶部要够到，手必须换握。
- 屏幕中心约 60% 是「看世界」的区域。HUD 进中心，角色和家具就会变难点。
- 触控目标至少 44px，游戏主操作更宜 48–56px。

所以竖屏养成的布局不是「把桌面侧栏竖过来」，而是重新划分：**世界占满，系统UI贴边，上下文面板盖住时也要留出角色。**

## 2. 参考作怎么做

### 《旅行青蛙》——世界即菜单

- 画面几乎全是庭院/室内。商店、行李、相册不是常驻底栏 App，而是点场景里的物件或角落入口。
- 青蛙在家时，玩家先看见它在干什么，再决定要不要点。
- 几乎没有数值条、没有聊天窗、没有「更多」里的设置堆叠。
- 可迁移原则：**能放进房间的功能，就不要做成屏幕按钮。**

### 《月兔奥德赛》——边角 HUD + 世界内对话

- 竖屏主界面把背包、手机、设置放在边缘，中间留给村庄/房间。
- 和好感、对话有关的信息出现在**对话进行时**（例如心形），而不是四条常驻进度条。
- 扩建、地图、日记是进了某个界面才出现，主画面保持干净。
- 可迁移原则：**关系/数值在事件里出现，不在首页常驻。**

### 《动物森友会：口袋营地》——底栏有效，但容易吵

- 明确采用竖屏、单手。主操作在营地里点角色和物件。
- 底栏放地图、制作、社交等「必须常在」的系统入口。
- 反面教材也很清楚：角标过多、站着不动就弹请求、同一信息出现在七八个入口。玩家会觉得催促，和治愈调性打架。
- 钓鱼/捉虫时 HUD 会退出画面，把屏还给当前动作。
- 可迁移原则：**底栏可以有，但条目要少；互动开始时 HUD 让路；不要用红点制造焦虑。** 宪章已禁止签到/红点催促，背包角标「8」要克制。

### 通用手游 HUD（动作/MOBA 可借鉴的部分）

动作游把摇杆放左下、技能放右下，是因为那是拇指热区。养成游戏没有摇杆，但同一条仍然成立：

- 常驻控件放底边，不要放顶角当主操作。
- 屏幕中心留给世界。
- 次要信息（设置、调试、完整数值）进抽屉或独立页。
- 键盘弹出时，输入条贴在键盘上方，镜头跟着对话对象。

不该从动作游戏抄过来的：虚拟摇杆、技能栏、小地图、顶条血量组。

## 3. 归纳成雯宝可用的布局规则

| 规则 | 含义 | 反例（当前竖屏） |
| --- | --- | --- |
| 世界优先 | 打开后先看见雯宝和房间，HUD 总高度宜控制在屏高 15% 以内 | 顶部大卡片 + 底栏，角色被夹在中间偏下 |
| 一句线索 | 今日故事最多一行，点开才看完整句 | 「此刻的小屋」三行卡片 |
| 底栏最多 3 项 | 回忆 / 布置 / 更多；聊天不是底栏项 | 「更多」展开后聊天、工坊、三组开关挤在一起 |
| 抽屉半高 | 「更多」最多约 40% 屏高，仍能看见角色头部 | 展开后约一半屏幕是面板 |
| 陪伴在世界里 | 说话、摸头、看纪念架都在她身上发生 | 聊天输入框在菜单底部 |
| 情境 HUD | 接球进度、饱腹提示只在相关动作时出现 | 「接球默契 1/3」常驻浮层 |
| 键盘让路 | 说话时只留她 + 一行输入 | 菜单开着再弹键盘，房间被挤没 |
| 触区 | 底栏与角色触区 ≥ 44px | 「查看」「发送」、勾选框偏小 |

这些与宪章第 5 条偏离检查一致：390px 上不得挡住角色和主要场景。

## 4. 建议的三种竖屏状态

只定义状态，不在本文件改代码。

### A. 观察（默认）

```text
顶：左名字胶囊（一行）     右背包（一颗）
    生活线索一行（可点展开 2 秒说明）
中：房间，镜头对着雯宝
底：回忆 | 布置 | 更多     ← 细条，含安全区
```

### B. 陪伴（点她之后）

```text
中：雯宝 + 身侧短气泡
底：单行输入（贴键盘） 发送
```

无数值、无设置、无模型状态。说完气泡淡出。历史进回忆录，不在首页做聊天列表。

### C. 更多（半高抽屉）

```text
上半：仍能看见房间和她的头
下半：四项状态（小格） / 工坊 / 镜头开关
      模型状态放最后，当调试
```

高度上限约 `min(40dvh, 320px)`，可滚，不得全屏。

## 5. 和现有实现的差距

竖屏已按第 4 节改过一轮：

- 今日故事默认一行胶囊，点开才展开说明，再点才走路。

PC 左栏仍保留完整状态；竖屏靠 `data-talking` 切换观察 / 陪伴，不把聊天列表做进首页。

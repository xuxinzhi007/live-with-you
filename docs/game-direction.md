# 雯宝游戏方向（摘要）

> 完整且具有约束力的产品、交互、内容与技术规格见 [产品宪章](./product-charter.md)。本文件只保留早期实现摘要；两者冲突时，以产品宪章为准。

## 产品定位

《雯宝》是一款以陪伴、布置和轻量照料为核心的网页放置游戏。玩家每天花一到三分钟看看角色、与她互动、调整房间；长时间停留时，也能观察她自主生活。它不是操作密集型小游戏，因此每个交互都应有明确的角色反馈。

## 平台策略

- **竖屏移动端优先**：主要目标为 360–430px 宽的单手使用。常驻界面只保留角色名、布置和菜单；状态与设置收在抽屉中。
- **横屏移动端**：不强制旋转，提供更宽的房间视野和更紧凑的底栏，适合布置和观察。
- **PC**：保留键盘快捷操作与更完整的状态面板；鼠标拖拽应与触控语义一致。
- 所有移动端主操作必须能在单指完成；双指只用于不影响游戏状态的查看房间。

## 核心循环

1. 角色按真实时间和离线时间产生轻度需求。
2. 需求通过角色表情、台词和头顶提示自然表达，而不是强制弹窗。
3. 玩家点角色或家具回应需求：点心补充饱腹、床恢复精力、玩具提升心情、互动增加亲密。
4. 街区的小事会带来零钱、纪念物；零钱能在花摊换花种，阳台种植、浇水、开花后可收成花束并陈列在家中。
5. 角色的状态、房间布局、收集物和照片在当前浏览器保存；回忆录图片在存储前压缩，保持移动端上传稳定。

街区的每个地点每天只会产出一次收获；完成后仍可陪角色停留，但不会反复刷资源。这样保留生活感与选择，而不是让玩家重复点击刷数值。

小纪念不是纯背包数字：会逐步出现在小屋的旅行纪念架上，角色能够走过去查看。长期成长优先采用这种可见的世界变化。

背包中只提供一条动态“生活线索”，根据当前资源和世界状态提示可能的去处；它不是每日任务、倒计时或强制目标，玩家可以完全忽略。

每日天气在本地稳定生成，改变环境氛围；小雨会替已种下的花圃完成一次浇水。天气应带来可观察的小变化，不以随机惩罚或强制在线为目标。

玩具球提供一条可选的即时互动：实际抛出、角色成功追到并接回三次，会形成一次“接球默契”纪念。它奖励操作与陪伴，不要求玩家重复刷取。

数值只能引导互动，不能造成惩罚或阻止继续游玩。角色即使状态较低也必须保持可互动。

## 移动端玩法基线

后续实现参照优秀手机休闲养成游戏的节奏，而不是把网页设置面板直接覆盖到场景上：

1. **看见**：进入后首先看到角色和场景；顶部仅有一条可忽略的生活线索，右上角是可展开背包。
2. **行动**：主操作永远在世界里完成——点角色、点物件、拖球、走到出口；底栏只保留布置和更多。
3. **反馈**：每次行动有角色移动、台词、特效或环境变化；奖励不以弹窗连发打断操作。
4. **积累**：街区收获、阳台花园、陪玩默契会变成纪念架、花束与生活小记中的长期变化。
5. **返回**：日常玩法控制在 30 秒至 3 分钟；玩家随时可以只停留观察、布置或互动，不会因离开受到惩罚。

常驻 HUD 预算：桌面不超过左侧小型角色胶囊、顶部生活线索和右上角背包；移动端不遮挡场景中心，信息与设置只在“更多”抽屉里展开。

## 交互原则

- 点角色是最直接的互动入口；点家具让角色走过去完成对应行为。
- 布置模式只改变静态家具，不影响角色；家具可自由重叠与上下摆放，但不允许拖出房间。小球等有重力或持有状态的道具由物理系统管理，不与家具布局混用。
- 手动平移镜头优先于自动跟随；角色开始行动时自动恢复跟随。
- 动画、爱心与对话必须有因果关系，避免持续或随机堆叠特效。

## 地点与自由生活

世界不应由一个塞满内容的房间构成。地点是独立的数据与体验单元：每个地点拥有自己的物件、可保存布置、环境氛围和角色行为；角色可在地点间来回，状态与关系保持连续。

当前已有三处可出行地点。地点之间不使用常驻“切换标签”；玩家点场景中的门、楼梯或路口，角色先走到出口，再选择下一站：

- **小屋**：休息、吃点心、玩具、音乐和回忆。
- **阳台**：看天、闻花、坐藤椅放空。
- **街区**：角色走到喷泉、花摊或长椅后触发偶遇，选择会沉淀为花种、纪念物或零钱。

后续以独立地点扩展，而不是把所有物件塞进同一房间：

- **客厅**：音乐、来访、合照。
- **更远的街区**：天气、偶遇、采集与小店。
- **朋友家或小店**：关系、交换与新的生活事件。

每个新地点至少提供一个独有交互、一个角色自主行为和一个可保存的布置区域。

## 上线验收

- 在 390 × 844 的竖屏中，首次进入能看清角色与房间，常驻 UI 不遮住主要互动区域。
- 在横屏与 PC 中，视野变宽但操作逻辑不变化。
- 切换菜单、浏览器地址栏变化或旋转屏幕后，手动镜头位置不会被意外重置。
- 所有进度写入失败时游戏仍可运行；构建产物可直接部署到 Netlify。
- 每次迭代需验证点角色、点家具、拖球、布置、菜单、回忆录与存档恢复，不以增加按钮数量作为进度标准。

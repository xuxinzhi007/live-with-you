# 产品分析 · 主大厅的展示 与 小世界的调整

> 日期：2026-11-13（Asia/Shanghai）。只分析、不改代码。
> 方法：pi 技能 `frontend-design` 的两遍流程（先取证与计划，再自评），证据全部来自仓库现状：DOM/CSS、世界数据、图片实际尺寸与内容。
> **实施状态（2026-11-14 凌晨）**：P0 全部落地（大厅地板/影子/信息条/行动带/自发动，小世界世界坐标+她走过去）；P1 完成「管线 + 3 张背景试点」，成图在 `tools/out/lobby-world/`，**过目通过后才替换 `public/assets/scenes/`**。
> 结论先行：**这两块效果不好的根因是同一个——「她不在场」。大厅里她站在一块粉色空卡上，小世界里她根本没出现。两块应该合成一个方向：同一个房间的两个镜头。**

---

## 一、先对齐「这两个屏是干什么的」

| 屏 | 玩家的 job | 现状是否完成 |
| --- | --- | --- |
| 主大厅 | ① 数秒内看到她和今天穿的衣服 ② 挑下一个动作（换装/闯关/抽卡） | ①做到一半（人可见，**衣服没有名字/星级/评分**）②按钮在，但都是浮层 |
| 小世界 | 「和她待一会儿」——陪伴的实体感 | **没做到**：这一屏没有任何角色在场 |

产品宪章的北极星是「打开数秒内看到雯宝和当前装扮」。大厅对了一半，小世界完全没对——这是分析的主线。

---

## 二、取证（现状到底是什么）

### 2.1 主大厅（`WorldApp.tsx:955-1160` + `world.css`）

| 层 | 现状 | 问题 |
| --- | --- | --- |
| 背景 | 装备中的**心境卡图**做全屏背景，`blur(8px)` + 透明度 0.48（`world.css:555`） | 概念是好的（心境决定氛围），但糊到认不出，实际观感 = 一片粉雾 |
| 舞台本体 | `.nk-bone-box` 228px（大厅扩展态 336px），角色立绘 `object-fit: contain` | 角色只占屏高约 28%–40%，脚下没有地面、没有影子接触点，是"贴在卡上"而不是"站在房间里" |
| 浮层 | 左上台词气泡 + 右侧 4 个 52×54 按钮竖排 + 顶部 2 个资源 pill + 金色内框 + 5 颗常驻星星 | **全是浮层，没有一层是"内容"**；金框和星与卡图风格打架，典型拼贴感 |
| 动效 | CSS 整卡呼吸（`nk-hero-breathe` 3.6s）+ 呼吸帧切换 + 常驻星星闪烁 | 三套动效同时跑，互相稀释；她本人的"生命感"反而最弱 |
| 信息 | 当前装扮的名字/星级/属性**不在大厅**，要点进衣橱才知道 | 北极星的"看到当前装扮"只完成了一半 |
| 台词 | 一句静态 `lobbyLine`，点她才换 | 陪伴感靠玩家先动手 |

### 2.2 小世界（`WorldScreen.tsx` + `rooms.ts` + `world.css:1917-2040`）

这是问题最大的一块，而且**不是美术问题，是渲染层把数据丢了**：

1. **世界坐标系是死的。** `rooms.ts` 认真设计了一套世界单位（注释：世界高 1000、地平线 y=640、可行走带 760–900、门高 340、道具按角色身高定标），还带了 `approach`（走近点）、`footprint`（阻挡）、`spawn`（进门落点）。`WorldScreen` 只用了 `x/w` 两个数：`left = x/worldW %`，所有道具**统一 `bottom: 12%` 一条线排开**（`world.css:1988`）。进深、地面关系、行走带，全部没有渲染。
2. **她不在场。** 没有角色、没有走动、没有坐下/躺下。点击家具 = 弹一句台词 + 1.5–3s 冷却 + 加 bond。所谓"和她待一会儿"，是一个没有她的房间。
3. **三种画风同屏。** 背景 `home/garden/street.webp` 是 1470×1500 的**扁平粉彩插画**；家具是 3–7KB 的 **flat 剪纸贴图**（`prop-bed.webp` 480×360，灰边明显）；而全产品最重要的一张脸——雯宝立绘——是**精细 anime 风**且不出现。现在屏上只有前两种，恰好是质量最低的两种。
4. **竖图被裁成一条。** 竖版背景（约 0.98:1）塞进 `min-height: 240px` 的横条 stage，`object-fit: cover` 只能露出中间一带——房间上半的窗、墙、挂画全部被裁掉。
5. **行走帧是闲置资产。** `original`/`maid` 各 4 张 `walk-*.webp` 已对齐 760 规格，全项目零使用（走路只存在于骨骼 FK 的关键帧里）。种花闭环的 5 张 `plot-*.webp` 同样只换图不演过程。
6. 坐标随屏幕宽度变化：道具宽度按 `% of 屏宽`，同一房间在 360px 和 430px 上比例关系不同——与 `rooms.ts` 注释宣称的"360–430px 同一空间关系"直接矛盾。

### 2.3 一句话诊断

> **大厅是"展示她"，但只给了一半信息；小世界是"陪伴她"，但人不在场。两者的素材（房间、家具、走路帧、心境卡）仓库里全都有，缺的是把它们接起来的那一层渲染与编排。**

---

## 三、方向：同一个房间，两个镜头

一个真实的空间，而不是两块互不相干的屏幕：

- **主大厅 = 这个房间的正面舞台**：她站在家里（地板线上，有接触阴影），身后是今天心境的"窗景"。
- **小世界 = 这个房间的完整平面**：同一条地平线、同一套家具，她可以走过去、坐下、躺下、浇花。

这样定的理由：① 复用率最高（房间背景、走路帧、坐躺帧、道具坐标全部已有或已在计划内）；② 直接回应"效果不好"的两个根因（大厅没环境、小世界没人）；③ 和"官方 Qwen 出游戏里能用的图"的现行路线对齐——缺的图都能走这条线补。

### 设计基调（沿用现有识别，不另起炉灶）

| 项 | 取值 |
| --- | --- |
| 色 | 现有 `#fdf6f8` 卡底、`#d4537d` 粉强调、`#ebd5dd` 描边保留；新增**暖木地板色** `#c8a274` 与**窗光色** `#fff3d6` 作为房间的两个锚点 |
| 形 | 圆角 16–22px 保留；去掉金色内框（`nk-stage-frame`），改用一道 1px 地板线 + 接触阴影表达空间 |
| 动 | 只留两处：她的帧动画（呼吸/眨眼）+ 进场一次的「她抬头看你」；常驻星星与整卡 bob 移除 |
| 招牌（signature） | **她每隔 45–90 秒自己动一下**：随机播 react 帧并冒一句台词；进小世界后，点家具她会走过去（walk 帧）再做出反应。生命感来自她自己，不来自滤镜 |

## 四、改造清单（按优先级）

### P0 · 主大厅（不动资产，纯 DOM/CSS/编排，半天～一天）

1. **舞台落进房间**：背景保留"心境决定氛围"，但从全屏 blur 改为「上半窗景 + 下半地板色带」两层；角色脚下加椭圆接触阴影 + 一条地板线。角色 `bone-box` 放大到屏高 55% 左右。
2. **装扮信息条**：她脚边一行 pill：`初雪白茶 · ★3 · 甜美 128`（数据 `computeOutfitStats`/`detectActiveSuit` 现成）。北极星的另一半在这里补齐。
3. **入口重排**：右侧竖排 4 按钮改为舞台底部一条行动带（换装/骨骼/闯关/幻阁，48px 高）；气泡挪到她头侧并加指向小三角。
4. **她自己是活的**：`setInterval` 45–90s 随机 `setReacting(true)` + 换一句台词（复用现有 `reacting` 状态与 `LOBBY_LINES`，约 20 行）；移除常驻星星与整卡 bob。

### P0 · 小世界（把已经设计好的东西接上，1～2 天）

5. **世界坐标真正渲染**：`bottom = (1 - y/1000) * 100%`、道具高 `h/1000`、按 `y` 排 z-index 与近大远小缩放；道具高改用世界单位，不再用屏宽百分比。这一步把 `rooms.ts` 355 行白费的数据全部救回来。
6. **她走进去**：角色渲染在 `defaultSpawn`；点家具 → `approach` 走过去（`walk-1..4` 帧位移补间 400ms）→ 播反应帧 + 台词 → 结算。**这一步同时救活三个闲置资产：walk 帧、（未来的）sit/sleep 帧、plot 五阶段。** 动作帧之前"放置"，正确落点就是这里，而不是大厅切静态图。
7. **标签降噪**：白底 pill 只在她的 1.5 个身位内或选中时显示。

### P1 · 资产统一（走官方 Qwen 线，正是"游戏里能用的出图"）

8. **三张竖版房间背景**（家/院子/街角），让 `cover` 不再裁成一条；同时第 8 条的"家·白天"可反哺大厅舞台。
9. **家具 14 件按角色画风重出**（或先把最常点的 5 件：床、书桌、花圃、喷泉、长椅）；剪贴感的 `prop-*.webp` 逐步替换。

### P2 · 玩法闭环

10. 种植上脸：花圃 UI 直接显示 5 阶段贴图 + 她浇水的反应帧；收获走现有 `sellFlowerBouquet`。
11. 经济打通（**需要你拍板**）：小世界 coins/种子与衣橱 coupons 是否换算。不拍板前两套照旧，不要暗改。

---

## 五、不做什么

- 不把小世界做成第二套重操作玩法（种田/建造），它仍然是"待一会儿"的轻陪伴场
- 不引入 Pixi/Canvas 引擎——世界单位用 `transform` 就够，单屏 ≤20 个元素
- 不在 P0 阶段动 `rooms.ts` 数据结构（数据是好的，坏的只是渲染层）
- 不为了统一画风把背景重画成 anime 细节风——背景保持"安静的平面"，把细节留给角色（也正是 Qwen 线擅长出的）

## 七、给排期的一句话

**先做 P0 的两条（大厅落进房间、小世界走进去）——它们不动资产、只动渲染与编排，一天内能看到"效果不好"被翻转；然后照着第 8、9 条把缺的图走 Qwen 线补上。**

自查（按 frontend-design 的两遍要求）：这版方案里"加信息条、挪按钮、加阴影"是任何换装游戏都会做的；真正属于《雯宝》的取舍是——**把"她自发地动"作为唯一的招牌动效**，以及**用小世界救活 sit/sleep/walk 三组闲置帧**（而不是为大厅单出姿势图）。这两条不是通用答案。

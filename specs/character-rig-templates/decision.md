- 级别：L3（为角色部件化定骨架/对位参考图；产出是图示，不改运行时代码）

- 真正要解决的问题：`docs/standard-character-plan.md` §11 引用了
  `standard-template-390.png`（5.0 / 6.0 两列骨架 + 关键点），文件不存在；
  现有的 `proportion-options-390.png` 只有 1.87 / 4.5 / 6.0 / 6.0 四档，
  缺文档 §0 推荐的 5.0，且全是方块人，做不了 §1.3 的「52px 脸可读」判断。
  结果：§9 的四个决策（头身比 / 旧档 / chibi 去留 / 场景重标定）无法拍板。

- 怎样算满足：
  1. 有 5.0 头身骨架图，关键点 y 值与 spec 算出来的完全一致，可被脚本重出。
  2. 关键点数值来自 `tools/character/spec.json`，不是手填的第二份数据。
  3. 有 52px / 39px / 125px 三档脸的可读性测试图，能直接看图做 §1.3 判断。
  4. `standard-character-plan.md` §11 不再引用不存在的文件。

## 已证实的矛盾（需要本次收紧）

`proportion-options-390.png` 第三格（6 头身·身体放大）把门画成 359px，
第四格（6 头身·身体不变）把门画成 269px。同一张图两种门高，读者会误以为
「只换角色不换家具」也能到 6 头身。本次新图必须显式标注场景是否同步标定。

## 最小充分方案

新增 `tools/character/make-rig-templates.py`，只画几何，不需要美术资源：

**图 B：`standard-template-390.png`（5.0 / 6.0 两列）**
- 左 5.0、右 6.0，各一张 760×760 画布缩放到 390 展示。
- 关键点从 `spec.frame` + `heads` 算：`头顶 = 748 - 720`、
  `下巴 = 头顶 + 720 / heads`，肩腰胯膝踝按 §2.2 的相对身高比例。
- 画：画布框、脚底线、中心线、每个关键点的横线 + 名称 + y 值 + 相对身高。
- 标注 5.0 与 6.0 的差异表（头高、下巴 y、可见宽）。

**图 A：`face-readability-390.png`（52px 脸测试）**
- 三档头高：125px（现状）/ 52px（5.0 下限）/ 39px（6.0 身体不变）。
- 每档用现有 `public/assets/characters/original/idle.webp` 的头部区域裁切缩放。
- 三个表情：现有资产只有 idle / react / sleep，正好对应中性 / 笑 / 困。
- 100% 缩放并排，不放大；标判定线「能否不放大区分三表情」。

**关键：数值单一来源**
脚本读 `spec.json`，并把算出的关键点写进图里的同时打印一份 JSON，
供 `standard-character-plan.md` §2.2 校对。不新增第二份手填表。

## 为什么更小的做法不够

- 只补一张 5.0 骨架图：仍缺 52px 脸测试，§1.3 的门过不了，§9 仍拍不了板。
- 只做 52px 脸测试：§11 悬空引用仍在，且没有对位模板无法开工。
- 手填数值画图：违反上一轮刚立的「规格单一来源」，立刻产生第二份会漂移的数据。

  这一点必须写进图注，避免被当成新底模的验收结论。

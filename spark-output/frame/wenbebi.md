# Frame — 雯宝（多人共处小世界）

- **生成时间**：2026-10-20T15:56:08+0800
- **数据源**：standalone（对话推方向）

## Persona

**开发者（情侣中的一方）**，给对象做陪伴游戏的人，技术背景（Go/Python/React），目前单独开发。

- **情境**：想和对象一起"待着"、彼此陪伴，但现有雯宝只有一个宠物角色、只能观察，自己不在场。
- **目标**：看到自己的角色在小世界生活，和对象的角色共同在场、实时互动。
- **当前 workaround**：现在只有一个雯宝角色，单人观察，对象没法进来。
- **挫败感**：点击没爽感、画面糙、玩法单调无聊、"总感觉缺少很多东西"。
- **"完成"长什么样**：打开游戏，看到自己（和对象）的角色在小世界里生活、能实时互动；每次互动有爽感，且有"打开就有期待"的钩子。

## 商业角度

- **为什么是现在**：现有版本手感糙、无钩子，开发者自己都觉得无聊；前端先行可快速迭代；后端（moe_social/backend，Kratos REST 单体）尚无实时通道。
- **谁付费**：无商业化（给对象 + 自用/好友小圈子）。
- **商业化**：无 / 成本中心（自娱 + 礼物）。
- **战略意图**：retention（陪伴关系留存）。

## 桌上的方向

**方向 A**：让"我"在场——角色创建 + 每次互动的 juice 反馈
- 用户价值：打开能看到自己，每次互动有爽感、不糙。
- 商业价值：共处的地基；纯前端、便宜、先于美术、快速见效。
- 最高风险假设：用户真的想要"自己"在场，而不只是看雯宝。
- 解决：机会 #1、#4

**方向 B**：让"我们"共处——对象的角色 + 角色间互动动词 + 留痕，实时联机后置
- 用户价值：彼此共同在场，角色间能互动，打开有期待。
- 商业价值：独有的钩子（别的放置游戏没有"另一个真实的人"）。
- 最高风险假设："共处"是解无聊的真正解药（未验证）。
- 解决：机会 #2、#3

**方向 C**：纯手感重做——不动"在场"，只把现有雯宝的点击做爽
- 用户价值：现有互动不糙、有爽感。
- 商业价值：最小改动、最快。
- 最高风险假设：只改手感不改"在场"，"无聊"会复发。
- 解决：机会 #4

## 我押

**方向 A** — 先把"我自己在这个世界里存在"做出来（角色创建 + 互动 juice），因为：① 它同时解决最痛的两条（没有"我"、手感糙）且纯前端、便宜、见效快；② 它是"共处"（方向 B）的必要地基；③ 不把最重的实时同步押在最没验证的假设上。

## 关键假设

1. 核心钩子是"一起玩"的共处时刻，而非独自每天打开（已被对象 3 问验证）。
2. 无聊的根因是"能做的太少"——需要围绕共玩时刻提供足够的互动。

## 压测结果（已用对象访谈验证）

**判断**：✅ 方向成立

**对象的三条回答**：
1. 多人方向确认——"肯定是多人这种"，但"每天打开不一定，偶尔看看，类似养"。
2. 无聊根因——"能做的太少"（不只是"没有我"）。
3. 打开时机——"大部分是一起玩的时候"。

**结论**：钩子是"一起玩"的共处时刻，不是独自每天打开；"养/偶尔看看"是低压力背景层。方向从"每日观察"调整为"围绕一起玩设计足够多的互动"。

**条件**：
- 先落地方向 A（角色创建 + 手感 juice）打地基，再进入方向 B（角色间互动/一起玩）。

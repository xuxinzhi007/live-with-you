# 文档形状

人和 agent 写文档用同一条。一篇只有一个主活。读者精力不够时，只读第一屏。

依据：[Diátaxis](https://diataxis.fr/start-here/) 四种页面、[Google 技术写作](https://developers.google.com/tech-writing/one/documents)（第一段答完）、[步骤规范](https://developers.google.com/style/procedures)（只给一条路）、[Wagtail](https://docs.wagtail.org/en/latest/contributing/documentation_modes.html)（混了就拆，开头互链）。

## 四种主活

| 读者此刻要什么 | 这一页只写 | 不写 |
|---|---|---|
| 把一件事做完 | 怎么做：一种走法，编号步骤 | 分叉、背景、全量清单 |
| 查某一个事实 | 速查：表，一行一条 | 道理、步骤 |
| 搞懂为什么这样分 | 解释：可以有观点 | 操作步骤 |
| 第一次跟着练 | 教程：一条成功路径 | 备选方案 |

一篇里出现第二种主活：拆出去，第一屏用一句话链过去。不要把后文抄进前一页。

## 第一屏

打开任何一篇，第一屏必须答完两句：

1. 这是干什么的。
2. 读者现在该做什么，或该停在哪。

关键句放段首。一段一件事。步骤只写最好的一条路；别的走法标成「旁路」，不写进同一步。

## 本仓库工件对上哪一种

| 工件 | 主活 | 第一屏 | 后文 / 另页 |
|---|---|---|---|
| `spec.md` | 拍板 | §1 本质一句话 + 已拍板的决定 | 事实表、九项、候选方案是速查，不在第一屏展开 |
| `impact.md` | 速查 | 四轴各一行结论，有没有阻塞 | 证据留在表里 |
| `plan.md` | 怎么做 | 接口改什么 + §3 的 3–6 步 | 不重开需求辩论；公司模板是归档，评审读一页方案 |
| `rollback.md` | 怎么做 | 能不能回滚，编号步骤 | 不写为什么当初这么设计 |
| `review/*.md` | 判断 | 结论：risk，停还是可以走 | findings 是表；范围外最多 3 行 |
| `change-note.md` | 速查 | §1 一句话 + 文档同步了没有 | 不复述 diff |

阶段文件里的 GATE、九项、审核清单是给作者的检查单，不是给读者的正文。检查单不抄进第一屏。

## 分层交付

给用户的分析按层给。结论层单独就能读。依据层和实施层等用户追问再写。`scope.md` 的核对问句、九项和债的分类留在文件里，不铺进第一份回复。

| 层 | 只回答 | 何时给 |
|---|---|---|
| 结论 | 要不要改。现在能不能改。下一步。这次不做，一行 | 第一份回复只有这一层 |
| 依据 | 为什么这样判断。查到了什么。哪些仍未知 | 用户追问为什么、证据或阻塞从哪来 |
| 实施 | 怎么改、怎么验证、风险、债怎么处理 | 用户追问怎么改、风险或债 |

结论层写不清「现在能不能改」时，先补那一句。同一函数、同一次事务、跨服务一致，在依据层分开写。看到实现之前，实施层只写方向；事务、幂等和历史数据怎么处理，留到看到入口之后。

## 协作

- 作者先写第一屏，再填表。第一屏写不出来，说明这篇的主活还没定。
- 评审默认只读第一屏和结论。要否某一条，再打开对应的表或 `文件:符号`。
- 后一步引用前一步，写路径和章节，不把上一步抄进来。
- 解释页可以有观点。步骤页不辩论。速查页不讲过程。

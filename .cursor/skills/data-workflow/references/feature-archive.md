# Feature Archive（功能归档）

把「刚完成的功能」蒸馏进知识图谱。单一产出纪律：**归档**。

- 写：稳定知识——接口契约、字段名、**事实源文件路径**、配置项落点。
- 不写：状态/枚举的具体取值、SQL 谓词、行数。这些一个 commit 就能让它们变假，且假了没有声音。只写「取值看该项目的事实源文件」（data-service 实例是 `internal/biz/status.go`）。
- 不写：易腐信息——行号、修订过程、版本对比、证据链推演（代码证据最多到符号名）。
- 不做：需求分析（上游已闭环）、技术设计（方案已落盘）、代码实现。

## 位置与上游

- 代码仓库：`$REPO`
- 知识图谱根：`$KNOW` 的上一级（`paths.sh` 解析；本身可能是 git 仓库，归档**不自动 commit**，除非用户明确要求）
- 技术方案源：`docs/architecture/<日期>-<主题>-技术方案.md`、`docs/API/*.md`
- 需求分析结论：对话中已闭环的结论；若未落盘，以技术方案「30 秒版 + 决策表」为准，用「本质一句话」重构定位段
- 现状核实：当前 checkout 代码（proto 字段/RPC、状态常量、配置取值、文件与符号名）——技术方案可能已过期，以代码为准

## G0 圈定范围（硬边界，先做）

先确定「归档哪个功能」，不猜、不全量扫：

1. 用户指名功能或给了技术方案文档路径 → 直接用。
2. 否则 `git log --oneline -20` + `git branch --merged` 找最近完成的功能分支/提交。
3. 对应到 `docs/architecture/` 里带日期前缀的技术方案文档；找不到就问用户要文档路径或功能名。
4. 范围确定后，先列出「本次要动的 vault 文件清单」再动手。

## 归档步骤

1. **读上游**：技术方案（决策层 + 契约层）+ 需求分析结论。只读，不复述。
2. **核对现状**：用当前 checkout 代码核实落点；方案与代码冲突时以代码为准，并在汇报里点明。
3. **判定归档形态**：
   - 新增状态/枚举/DisplayStatus/DataStatusOption → 更新 `knowledge/状态机.md`。
   - 新增/变更 API → 更新 `knowledge/接口总览.md`。
   - 全新模块 → 新建 `knowledge/<模块>.md`（单文件）或 `knowledge/<模块>/README.md`（多文件导航）。
   - 已有模块扩展 → 更新对应 README，不新建文件。
4. **写内容**：蒸馏稳定知识，中文，简洁无废话。
5. **接线**：更新 root `README.md` 导航与目录树（新模块必须登记）；相关模块 README 的「关联」段；接口总览。
6. **死链校验**：全库扫 `[[...]]` 链接，确保 0 死链（文件夹用 `[[模块/README]]`，不用 `[[模块]]`）。
7. **汇报**：改动文件清单 + 每个文件加了什么，不超过一屏。

## Vault 约定（必须遵守）

- `knowledge/状态机.md` 是**唯一**状态/枚举来源。新增枚举一律写进这里；模块 README 只留链接 + 该模块独有业务规则（如收敛优先级、推导公式、quality_status 映射）。
- 模块两种形态：单文件 `knowledge/<模块>.md`；多文件 `knowledge/<模块>/README.md` 导航 + 子页。
- root `README.md` 是唯一入口（快速开始 + 模块导航 + 目录树 + 仓库对照）。
- 历史/过时内容进 `knowledge/归档/`；零散工作记录进 `knowledge/归档/工作记录/`。
- 中文正文与命名；wiki 链接 `[[目标]]` 或 `[[模块/README]]`，锚点用 `[[状态机#章节]]`。

## 蒸馏原则

- 一个功能一张卡/一节：先「是什么 / 做了什么 / 影响什么」，再「接口 / 状态 / 配置 / 落点」。
- 状态与模式用业务名（待分发/执行中），枚举值统一见状态机.md。
- 需求分析的「本质一句话」与「不做什么」写进模块 README 定位段；技术方案的契约表写进接口/状态章节。
- 无技术方案的功能：从 git diff + 代码蒸馏最小卡，只写契约/状态/落点，不补写设计。

## 完成标准

- 范围清单内每个文件都已按约定更新。
- 新增/变更的状态、枚举、接口都已落到状态机.md / 接口总览.md。
- root README 导航与目录树与实际结构一致。
- 全库 0 死链。
- 汇报不超过一屏。

# 复用门禁（Skill 版）

**不再依赖 stop hook 强制追问**——由 Agent 在 Go 改动完成前主动读本 skill 并自检。

## 何时执行

- 本次对话中修改或新增了 `*.go`
- 即将结束实现任务、回复用户「已完成」之前
- 用户显式要求「复用门禁 / 自检」

纯问答、未改 Go：跳过。

## 自检清单（对照 R14–R18）

1. **复用**：新逻辑是否已在 `internal/pkg/helper`、同 Usecase、同 Repo 存在？有则删掉新写的，改调已有。
2. **死代码**：本次新增但未被调用的函数、字段、文件必须删。
3. **冗余**：无平行调用链、SkipXxx、仅中转 DTO、为筛选铺的一次性 helper。
4. **调用链**：沿用 service → biz → data；独立 `cmd/` 运维脚本除外。
5. **历史屎山**：只触及本次路径上的重复/死代码；更大问题只汇报、等用户确认。

## 扫描范围

- **仅统计将要合入的 Go 改动**（`git diff` 已跟踪文件）。
- **未跟踪的本地脚本**（如 `cmd/seed-job-labels`）若明确不合入主 PR，不计入主服务死代码告警。

## 结束前必答（有 Go 改动时）

回复末尾附：

```
- 复用了: …
- 新建了: …（无则「无」）
- 触及式清理: …（无则「无」）
- 复用门禁：通过
```

发现问题先改代码再回复；无问题则简短列出上述四行。

## 与 ponytail 分工

| Skill | 管什么 |
|-------|--------|
| **reuse-gate**（本 skill） | 复用、调用链、死代码、触及式清理 |
| **ponytail / ponytail-review** | 过度抽象、可删代码、stdlib 替代 |

两者可同时用；Go 实现任务默认先 reuse-gate，复杂 diff 可加 `/ponytail-review`。

# <主题> 回滚预案（rollback）

> 产出者：`stages/tech-design/SKILL.md`（方案阶段写）＋ `stages/impact-assessment/SKILL.md`（轴 4 取证）。落 `specs/<feature>/rollback.md`。
> 形状：`references/doc-shape.md`。主活是怎么做。第一屏是能不能回滚，加上编号步骤。
> 规则：**别人照着这些步骤能回到改动前的状态。**「回滚代码即可」不算预案。
> 上线前写，不是出事后写——出事后写的叫事故报告。

- feature：`<name>` ／ 分支：`<branch>` ／ 目标 commit：`<sha>`
- 发布方式：`<灰度 / 全量 / 配置先行>`

## 1 判定：这次改动能不能回滚

| 维度 | 结论 | 依据 |
|---|---|---|
| 代码可逆 | 是 / 否 | revert 是否足够，是否依赖发布顺序 |
| 数据可逆 | 是 / 否 / 部分 | 新增列、已写入行、已变更状态各自能否逆向 |
| 可半回滚 | 是 / 否 | 开关名与默认值；无开关时属哪种允许情形 |

> **GATE：数据不可逆 + 无备份 + 无重放路径 = 阻塞，回需求阶段重做方案。**

## 2 代码回滚步骤

```

```

## 3 数据回滚步骤

```
1. <新增列：保留 / 删除；删除前确认没有写入的检查 SQL（只读）>
2. <已写入的 N 行 / 已变更的状态：逆向脚本路径，或「不可逆」>
3. <不可逆时：备份位置、重放方式、最坏影响是什么>
```

**只读检查 SQL 贴在这里**（不含真实数据，字段名脱敏按需）：

```sql
-- select count(*) from <table> where <new_column> is not null;
```

## 4 半回滚 / 降级

| 开关 | 位置 | 默认值 | 关掉后的行为 | 旧数据怎么处理 |
|---|---|---|---|---|

无开关时说明属于哪种允许情形：

- [ ] 只读改动（回滚 = 前端不再调）
- [ ] 纯幂等写（重放不会产生副作用）
- [ ] 可重放（有补偿任务 / 消息可重投）
